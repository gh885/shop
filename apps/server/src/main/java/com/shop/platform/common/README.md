# common — 纯契约

共享包。**被所有模块依赖，所以它自己的依赖必须干净。**

## 放什么

| 子包 / 类           | 是什么                                          |
| ------------------- | ----------------------------------------------- |
| `id/Ids`            | UUIDv7 生成，主键与事件 ID 的唯一来源           |
| `id/BizNo`          | 对外业务号：前缀 + 日期 + 12 位随机，本地生成   |
| `id/BizSequence`    | 连续号段发号器，走 `common.biz_sequence` 行锁   |
| `event/DomainEvent` | 领域事件接口，只约定「必须自带生产端生成的 ID」 |
| `money/Money`       | 金额唯一形状：整数分 + ISO 4217 币种            |
| `ErrorCodes`        | 错误码常量，来源是 `contracts/error-codes.yaml` |
| `BusinessException` | 业务异常，携带状态码 + 可选 code + 字段级明细   |
| `ValidationRules`   | 字段校验规则词表，前端据此出自己语言的那句话    |

## 不放什么

**任何需要连库或连网的东西。**

判据：加了它之后，`common` 会不会被迫引入一个基础设施依赖？会，就放 `infra`。
`common` 被三十多个模块依赖，一个 Spring Data 进来就是全网扩散。

`AuditRecorder` 一度放在这里，后来搬去 `audit` 模块——它有自己的表，按 module-map 的判据它就该是模块。

## 三套号的分工

| 用途                       | 用什么        | 允许空号 |
| -------------------------- | ------------- | -------- |
| 表主键 / 事件 ID           | `Ids.newId()` | —        |
| 订单号 / 支付流水号        | `BizNo.of()`  | 是       |
| 凭证号 / 发票号 / 对账单号 | `BizSequence` | 否       |

为什么 `BizSequence` 不用 PG 的 `SEQUENCE`：sequence 在事务回滚时不回退，必然留空号。它是一行普通数据，
更新和业务写在同一个事务里，回滚就一起回滚——测试里有一条专门断言这件事。

## 改这里的代价

它是所有模块的公共依赖。**类名、方法签名改动的影响面是全部模块**，加东西前先问一遍：
这是不是只有一个模块要用？是的话就不该在这里。

## 闭环状态

- 发号：闭环（并发、回滚、号段三种情况都有测试）
- `Ids.newId()` 目前只有测试在用——业务模块还没有需要它先生成 ID 的地方，这是正常的
