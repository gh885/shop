# 淘宝对标：业务规则差距清单

> 用途：把本库各域的生效规则与淘宝（含天猫）的同类规则逐环节对照，分出「结构一致 / 刻意简化 / 真正缺口」三类，供排期与拍板。**本文不是生效规则**，不进编号体系；条目里的规则号（如 ORD-27）指向本库对应条款。
> 口径：淘宝规则版本会浮动（天数、赔付比例常改），本文取长期稳定的机制口径；落地前以淘宝规则中心现行版本复核具体数字。
> 维护：某条差距拍板后（做 / 不做 / 改口径）在对应行末记结论；已落地的从表里删掉、挪进「一致」行并回写规则文件。基线：2026-09-22，含 C1～C15 与 P0 首批（ORD-59 / ORD-60 / ACC-74 / AFS-42 / AFS-43 + LOG-17）落地后的规则版本。

## 一、订单 / 购物车

| 环节           | 本项目                                                                                                                                        | 淘宝                                                                             | 差距评价                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 待付款关闭     | 下单起 15 分钟（ORD-26）                                                                                                                      | 一般商品默认 3 天，卖家可调；天猫与活动类目 1 天或分钟级                         | 15 分钟是票务/外卖口径，零售偏短；多店逐单支付（ORD-41）还共用这一个窗口                                                                                |
| 库存扣减与恶拍 | 拍下冻结、付款扣实（ORD-11 / PRD-50）；下单查账号状态（ORD-54）；结算行数封顶 99、在途待付款 ≤10 单、24h 内拍下不付 ≤10 单（ORD-03 / ORD-59） | 卖家可选「拍下减 / 付款减」，并限制拍下不付款次数过多的买家                      | 机制已齐（行数 + 并发待付款 + 不付次数三道），比淘宝多的是「按单计」而非「按信誉分档」；阈值 10/10 是拍的，没做买家分级与卖家自选扣减模式               |
| 买家取消       | 待付款、待发货都可即时取消，待发货取消即退款（ORD-20 / ORD-33）                                                                               | 待付款可直接关闭；待发货只能「申请退款」，卖家可凭已发货拒绝，超时未处理视为同意 | 即时取消对买家友好，但卖家零防御：货已交快递、单还没录，买家一点即退                                                                                    |
| 卖家发货时限   | 付款起 3 天记 `ship_expire_at`，到期**只提醒不关单**（买家卡片红字 + 卖家「超时未发货」徽章，ORD-27 / ORD-60）；取消由买家手点（ORD-20）      | 淘宝 48 小时、天猫 72 小时；逾期不关单，买家可申请退款并获延迟发货赔付           | 选择权已同淘宝交给买家（原「到期系统自动取消」已废）；仍缺的是逾期**赔付**（延迟发货补偿金）这一层，平台暂无资金科目承接                                |
| 确认收货       | 发货起 7 天，签收后重算 7 天（ORD-28）；售后单未落到终态前系统不自动完成（AFS-43）                                                            | 快递发货后 10 天自动确认，买家可申请延长                                         | 签收重算更合理，且不给「争议未决却自动收货」留口子；缺「买家延长收货」入口，物流慢时只能被动等自动完成                                                  |
| 待收货期间退款 | SHIPPED 即可申请售后，类型不挡（AFS-01 / AFS-43）；包裹 RETURNED 从退回时刻重算收货窗口（LOG-17）；自动确认收货让位给进行中的售后单（AFS-43） | 已发货即可申请退货退款或仅退款，可拒收                                           | 已对齐（2026-09-22 落地，补原「售后须等 COMPLETED」的流程断点）；仍缺的是「拒收」这个显式买家动作——目前由物流侧 RETURNED 事实承载，买家不点也拿不到出口 |
| 售后窗口       | 完成起 15 天（ORD-29 / ORD-53）；待收货阶段不设截止，完成时才回填 `apply_expire_at`（AFS-02）                                                 | 交易成功后 15 天                                                                 | 一致；待收货那段不倒计时是 AFS-43 顺带定的——货都没到就开始算 15 天没有意义                                                                              |
| 争议处理       | 卖家拒绝后买家只能重复申请（AFS-04）                                                                                                          | 平台介入 / 小二仲裁                                                              | 买家没有终局救济                                                                                                                                        |
| 七天无理由     | 无此概念，理由可选（AFS-10），卖家可任意拒绝（AFS-20）                                                                                        | 签收后 7 天无理由退货为平台强制，卖家不得拒绝（特殊类目除外）                    | 法定要求（消保法第 25 条），不只是平台惯例                                                                                                              |
| 仅退款口径     | 整单实付含运费全退、货不退（ORD-40 / AFS-13）；48 小时不处理自动同意（AFS-23）                                                                | 已收货仅退款多为部分金额协商；整单退货才全退，无理由退货运费买家承担             | 整单口径下「仅退款」等于买家留货全额拿回；超时自动同意上线后卖家漏看 48 小时就货款两空，风险被放大                                                      |
| 合并支付       | 按店拆单后逐单支付（ORD-41）                                                                                                                  | 多店一次合并付款                                                                 | 逐单支付叠加 15 分钟窗口，多店体验差；接真实网关前应先定合并支付单模型                                                                                  |
| 改价 / 改地址  | 都不支持，地址下单即快照（ORD-07）                                                                                                            | 卖家待付款可改价改运费；买家发货前可改地址                                       | 改地址是高频客服需求，快照模型下可做成「发货前改快照并留痕」                                                                                            |
| 卖家动作       | 发货与追加包裹（ORD-19 / ORD-55）                                                                                                             | 另有关闭待付款单、改价、修改运单号、主动退款                                     | 修改运单号最紧要：正向运单号全局唯一且不可改（ORD-37 / LOG-10），录错只能再追加一个包裹                                                                 |
| 取消原因       | 快捷原因 + 备注拼成自由文本落库（ORD-57），不造枚举                                                                                           | 枚举原因，可统计                                                                 | 体验已对齐；要做统计或恶拍判定时需补枚举列                                                                                                              |
| 评价           | 无                                                                                                                                            | 交易成功后 15 天内评价，超时默认好评                                             | 销量有了（PRD-48），评价没有，转化链路缺一半                                                                                                            |

- **一致的**：一店一单拆单、已完成不可取消、无「已取消」页签、留言 200 字且结算页可填（ORD-58）、售后线与主状态正交、待付款倒计时、自动确认收货后仍享完整售后窗口、多包裹追加发货入口（ORD-55 / ORD-56）、五份契约都下发动作集（ORD-19 / AFS-40，卖家订单行按本页订单批查）、购物车容量量级（99 种 SKU 对淘宝 120 件后扩到 300）、待收货给售后出口（AFS-43）。
- **不必跟的**：运费险、跨店满减与红包叠加、卖家备注旗帜、完整商品页交易快照、订单回收站、按仓拆单。

## 二、售后 / 退款

| 环节         | 本项目                                                                                                                                                                         | 淘宝                                                                                       | 差距评价                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 可发起阶段   | 待收货（SHIPPED）与已完成（COMPLETED）两段都给，且须窗口未过、无进行中单、上一张非 REFUNDED（AFS-01 / AFS-43）；待发货不给                                                     | 待发货（仅退款）、待收货（退款 / 退货）、交易成功后 15 天                                  | 已对齐（2026-09-22 落地）；待发货段是拍板不跟——那一段买家的出口是 ORD-20 取消退款，不再开第二条退款通道                           |
| 售后类型     | 仅退款 / 退货退款（AFS-08）                                                                                                                                                    | 仅退款 / 退货退款 / 换货（部分类目维修）                                                   | 换货缺席可接受                                                                                                                    |
| 粒度         | 整单，退款额 = pay_amount（AFS-09 / AFS-12）                                                                                                                                   | 按子订单（商品行）退，金额可改（≤ 实付）                                                   | 整单是 V1 定案；但整单「仅退款」没有协商空间                                                                                      |
| 原因与凭证   | 理由可选自由文本 200 字，无凭证（AFS-10）                                                                                                                                      | 原因枚举必选（无理由 / 质量 / 描述不符 / 发错少件…），可上传图片；原因决定运费责任与举证方 | 原因枚举是运费责任、无理由强制、统计三件事的前提                                                                                  |
| 卖家收到退货 | 两条边都有：确认收货即退款并回补（AFS-18 / AFS-38），验货不通过可拒绝退款（REJECT_RETURN，AFS-20）；买家填单后卖家超 **10 天**未确认收货 → 系统自动退款并回补（AFS-23 第三条） | 可拒绝退款并举证进平台介入；超时未处理系统自动退款                                         | 已对齐（2026-09-22 落地）：两头都不再悬挂。缺的从「没有出口」变成「出口没有裁判」——拒绝只留一行理由，谁对谁错判不了，见「争议」行 |
| 退货地址     | 售后详情实时下发卖家默认退货地址，未配则提示联系客服（AFS-42）                                                                                                                 | 同意退货时系统给出卖家退货地址                                                             | 已对齐（2026-09-22 落地）：差距是「无消费点」而非「无数据」，故补下发不做快照                                                     |
| 争议         | 拒绝后可无限重复申请（AFS-04 / AFS-40 REAPPLY），拒绝必须给理由且随买家详情下发（AFS-30 / AFS-44）                                                                             | 修改申请 / 申请平台介入，仲裁终局                                                          | 无仲裁通道：协商有了台词、没有裁判，卖家反复拒就是死循环                                                                          |
| 运费与退款额 | 全额含运费（AFS-13）                                                                                                                                                           | 未发货全退含运费；已收货按原因分责，无理由退货运费买家承担；部分退不退运费                 | 依赖原因枚举                                                                                                                      |
| 七天无理由   | 无概念，卖家可任意拒绝（AFS-20）                                                                                                                                               | 签收 7 天内平台强制，卖家不得拒绝（特殊类目除外）                                          | 法定要求                                                                                                                          |
| 协商留痕     | 时间线只落库，对外仅读出「拒绝理由」一项随买家详情下发（AFS-22 / AFS-44）                                                                                                      | 买卖双方可见协商记录                                                                       | 有仲裁才需要完整留痕，可与仲裁一起做                                                                                              |
| 卖家主动退款 | 无                                                                                                                                                                             | 卖家可主动发起退款                                                                         | 缺货 / 议价场景常用                                                                                                               |

- **一致的**：卖家 48 小时不处理视为同意、买家 7 天不寄回自动关闭、卖家 10 天不确认收货自动退款（AFS-23）、售后动作集后端下发（AFS-40）、回寄运单可覆盖重交（AFS-41）、售后状态与主状态正交、REFUNDED 后订单仍 COMPLETED、已退款不可二次申请、被拒 / 撤销可重申、同一订单同时只一张进行中售后、退款与退券退库存同事务。
- **不必跟的**：极速退款（信用先赔）、运费险、换货流程。

## 十、跨域全局缺口

- **通知**：全站无消息体系（短信 / 站内信 / 推送）；淘宝每个状态变化都通知买卖双方。
- **评价**：无。
- **平台治理**：商品下架、封店、售后仲裁三个动作无端点（封号已有，ACC-71）。
- **资金**：无托管 / 结算 / 分账，「确认收货」不触发任何资金动作。
- **合规**：七天无理由、账号注销、划线价依据、违禁词、手机号对卖家脱敏。

## 十一、优先级汇总

- **P0（流程断点、法定、资金与库存安全）**：**还剩两条**——① 七天无理由强制（消保法第 25 条，依赖售后原因枚举 AFS-10 与「特殊类目除外」的可退标记）；② 账号注销（个保法第 47 条）。
  已落地的记在这里，别重复排期：恶拍防护整条（行数 ORD-03 + 在途待付款与拍下不付计数闸 ORD-59）、超发货时限改「只提醒 + 买家选择」（ORD-60，系统不再代关单，前端死按钮「提醒发货」删除）、被拒店铺原地重提（ACC-74）、退货地址实时下发（AFS-42）、待收货售后出口与包裹 RETURNED 联动（AFS-43 + LOG-17，含「售后未决时自动确认收货让位」）、卖家收到退货的拒绝退款路径与确认收货超时（AFS-20 REJECT_RETURN + AFS-23 第三条 AUTO_RECEIVE + AFS-44 拒绝理由下发），均为 2026-09-22。
  售后线只剩平台仲裁：它要新开进行中状态、`TicketActor.PLATFORM`、admin 端点与权限码，是一块独立的活，不塞进本轮。
- **P1（体验与经营）**：合并支付单模型；正向包裹修改运单号与「无需物流」发货；发货前改地址；售后原因枚举 + 凭证 + 仅退款金额可改；消息通知；销量按付款计 + 销量排序；评价体系；手机号对卖家脱敏；违禁词检测；取消原因枚举列。
- **P2（运营与治理）**：封店 / 解封端点；平台商品下架；定时上下架；券递进口径（随 N5）；每人限购；买家延长收货；发票；店铺页；划线价依据说明；实名与保证金（随结算）。
