# 优惠券 / 营销

> 代码入口：apps/server/.../coupon；order/aftersale 对 coupon::api 的调用点；apps/web（checkout/coupon）、apps/seller（coupon）。规则以代码为准沉淀，改代码请同步本文件。

## 券类型与范围

- **[CPN-01]** 一期只有一种券：「满 threshold 减 discount」（threshold=0 即无门槛券）；表上无 `type` 判别列，只有 `threshold_amount` + `discount_amount`（分）两列，折扣券/运费券留待二期以加列方式增量演进。
- **[CPN-02]** 只做店铺券：模板与用户券 `shop_id` 非空，券范围 = 本店全部商品（无品类/SPU/SKU 圈品），结算与核销天然落在按店拆单的单笔订单内、零分摊；平台券（跨店）在三期。
- **[CPN-03]** 承担方枚举 `CouponBearer = SELLER | PLATFORM`（DB CHECK 两值），一期店铺券恒 SELLER（从卖家货款扣，将来结算拆账用）；承担方沿「模板 → 用户券快照 → 订单快照」传递，order 侧不硬编码。
- **[CPN-04]** 币种全链只有 CNY：`coupon_templates`/`user_coupons`/`coupon_usages` 三表各有 `CHECK (currency='CNY')`；券与本单基数币种不一致时判不可用（CURRENCY_MISMATCH），不做汇率换算。
- **[CPN-05]** 券的价值锚点只有「减金额」：兑换券/赠品券（换商品）不做（会把订单行模型撕成两半）。

## 建券与卖家管理

- **[CPN-06]** 建券条款：券名必填 ≤60 字（trim）；减免额必须 >0；门槛 ≥0；门槛 >0 时减免额不得超过门槛（防「满 100 减 200」填反，无门槛券减免无上界）；`validTo > validFrom`；发放总量为 [1, 1_000_000] 的整数；金额币种必须平台币种（非 CNY 入参即 400）。卖家前端 Zod 预检同一口径（元→分、本地时间→ISO），后端仍是权威。
- **[CPN-07]** 新建模板建好即 ACTIVE 可被领取；有效期起点由卖家给定（可未来）。未到起点的券会进买家可领列表但标 `claimable=false`（C9，见 CPN-63），领券端点仍拒未开始，因此一期没有「领了但暂未生效」的用户可达路径。
- **[CPN-08]** 没有「改券」：卖家侧只有列表 / 建券 / 停券三个端点，要调整规则只能停旧建新（已发出的券是快照，改模板只影响后来人）。
- **[CPN-09]** 停用（ACTIVE→STOPPED）只停止继续领取，已领出的券照旧可用；模板刻意不软删（券的溯源不能断线）；对已停用的模板重复停用返回 409。
- **[CPN-10]** 卖家券操作需 `COUPON_MANAGE` 权限，shopId 取自 `X-Shop-Id` 店铺上下文（前端不传店 ID）；越店访问与不存在一律 404，不泄露券的存在性。
- **[CPN-11]** 卖家列表每行带「已发放数（issued_quantity）」与「已核销数（usedQuantity）」两个绝对数（不合成核销率）；已核销只数 USED 实例，LOCKED 占用中的不算成交；两者差额 = 领了没用掉的。
- **[CPN-12]** 卖家券列表展示状态由「模板 status + 有效期区间」派生：STOPPED 优先显示「已停用」（哪怕时间窗未开始）；起点闭区间、终点开区间（`validFrom<=now<validTo`）为「进行中」，否则「未开始/已结束」；时间解析失败回退「进行中」（不主动宣称作废）。判定口径与后端评估器对齐。

## 领取

- **[CPN-13]** 店铺可领券列表匿名可访问（`GET /api/shops/{shopId}/coupons`），返回 ACTIVE 且未过发放结束时刻的券（未到起点的也列出并标 `claimable=false`，C9，见 CPN-63），按创建时间倒序；领完的（issued≥total）仍在列表里出 `soldOut=true`（前端置灰「已领完」而非消失）；匿名通道刻意不返回「我领过没领过」。
- **[CPN-14]** 领券（`POST /coupons/{templateId}/claim`，201）要求登录；失败反馈区分：模板不存在/已停用/未开始发放/已结束发放 → 400 各自文案；已领完 → 409。
- **[CPN-15]** 每人每模板限领 1 张（一期固定 1，非可配）：友好判重（只按 `source=CLAIM` 查重，退款补发券不挡领取）+ 部分唯一索引 `uk(template_id,user_id) WHERE source='CLAIM'` 兜底并发；两条路径同返 409 + 错误码 `COUPON_ALREADY_CLAIMED`（前端据此标「已领取」，不引导重试）。
- **[CPN-60]** 领券撞 `COUPON_ALREADY_CLAIMED`（409）的前端行为按 code 分支、不只按 status——409 还可能是「已领完」（CPN-14/16），二者文案相反；命中该码提示「已领取」而非「领取失败」，并用 `silentError` 退出全局错误 toast，不与浮层/按钮就地态（见 CPN-56）叠加弹错。
- **[CPN-16]** 发放总量超发由单条条件 UPDATE 闸住：`issued_quantity+1 WHERE status='ACTIVE' AND issued<total AND now∈[validFrom,validTo)`，影响 0 行即 409「已被领完」；顺序是先扣名额再插券，插券撞唯一索引整个事务回滚（名额不白占）。
- **[CPN-63]** 未开始的券对买家可见（C9）：可领列表的时间过滤只留 `validTo > now`，起点不再硬过滤——预告是营销位，「x 点开抢」看得到才有蹲点领取，消失等于用户以为没办活动。每行回传 `validFrom` + `claimable`（= 已到起点且未领完；列表内 ACTIVE/未结束由查询保证）；前端对 `claimable=false` 且非 soldOut 的行出禁用按钮（文案含开抢时刻；SDK 类型追平前旧响应校验会剥掉 claimable，此时回退用本地时刻比较 validFrom）。领券端点维持 CPN-14/16 的时间窗拒绝——**露出是预告，不是放行**，两道闸独立。
- **[CPN-17]** 领取即固化快照：券名/门槛/减免额/币种/承担方/有效期（换算成绝对 `effective_at`/`expire_at` = 模板 validFrom/validTo）整份复制进用户券行，此后读券（券包、结算判定）零回查模板，模板被改被停与已发券无关。

## 使用门槛与减免计算

- **[CPN-18]** 门槛基数 = 同店适用商品的销售价小计（单价×件数求和），不含运费、不含划线价、不含任何其他优惠；采用平行优惠口径（各优惠基于原始金额独立判定），刻意不用递进口径。
- **[CPN-19]** 门槛判定「基数 ≥ threshold」即满足（等于也算达到）；threshold=0 恒过。
- **[CPN-20]** 可用性判定次序固定：时间（未生效 → 已过期）→ 币种 → 门槛；不可用一律带原因码，不允许只回 boolean。
- **[CPN-21]** 时间判定以绝对时刻为准：`now < effective_at` → NOT_EFFECTIVE；`now >= expire_at` → EXPIRED（等号时刻即已过期）；不看 status 列（状态列只是展示投影，由收敛任务维护，正确性不押在调度器上）。
- **[CPN-22]** 可减金额 = min(面额, 门槛基数)：100 元券用在 50 元单上只减 50，余额作废、不找零（满减券是一次性权益不是可找零余额），并保证实付不为负。
- **[CPN-25]** 结算预览与真实下单强制走同一条计算链（同一个 `groupByShop` + 同一个无 IO 评估器），「预览一个价、下单另一个价」在结构上不可能；后端不自动选券，`appliedCouponId` 只是回显请求里选的 id。
- **[CPN-26]** 不可用原因码四个：NOT_EFFECTIVE（尚未生效）/ EXPIRED（已过期）/ THRESHOLD_NOT_MET（未达门槛）/ CURRENCY_MISMATCH（币种不符），每个自带兜底文案；前端文案与后端逐字对齐，未知码回显码本身。

## 选券、叠加与互斥

- **[CPN-27]** 一笔（按店拆出的）订单至多核销一张券；一店选了多张也只有第一张落地，第二张必因「未落地」被 400 拒绝。
- **[CPN-28]** 一次结算请求最多携带 20 个 `userCouponIds`（多店各一张的场景上限）；同一张券重复传去重只用一次；不传 = 不用券。
- **[CPN-29]** 结算候选 = 买家在本店 `status=UNUSED` 的券（LOCKED/USED/已由任务收敛的过期券不进候选）；评估结果连不可用者一并返回。
- **[CPN-30]** 候选排序固定：可用在前 → 本单可减金额大在前 → 同额到期早在前 → id 兜底（可用在前 → 减得多 → 先过期）；前端照单渲染、不再重排。
- **[CPN-31]** 默认选券是业务决策：默认选「候选中第一张可用券」（优惠最大优先，快到期为次序），允许用户手动切换或明确选「不使用优惠券」；选券选择只在补齐未表态的店时填默认，用户已表态的（含选「不使用」）绝不被后续预览覆盖。
- **[CPN-32]** 选了却不可用绝不静默忽略：选中的券被评估为不可用 → 400「优惠券「名称」不可用：<原因文案>」；券不属于本单任何一家店或已不在候选集 → 400「所选优惠券不可用于本单，请重新选择」。
- **[CPN-33]** 无叠加/互斥组模型：一期一店一券即消灭「先用哪张」的问题（结构性消歧，不靠口诀）；自动促销与券的叠加点问题一期不存在。

## 状态机与生命周期

- **[CPN-34]** 用户券状态机：`UNUSED →(下单占用)→ LOCKED →(支付成功)→ USED`；`LOCKED →(取消/超时关单释放)→ UNUSED`；`UNUSED →(时间到)→ EXPIRED`；`UNUSED/LOCKED →(运营作废)→ VOID`（一期实现只开 UNUSED→VOID，见 CPN-62）。LOCKED 不可省（否则一张券可被多笔未付款单同时用掉）；USED 不可逆。
- **[CPN-35]** 下单占用（lock）与订单落库同事务：条件更新 `UNUSED→LOCKED`（写 order_id/locked_at/applied_discount_amount），影响 0 行 → 409「该优惠券已被其他订单占用或已失效」→ 整笔下单回滚；并发闸门在条件更新，不做读-改-写。串行场景下，被占的券早已不在候选集，会先被 400 拦下，409 是并发下的最后防线。
- **[CPN-36]** lock 的三道前置护栏：券必须属于本人（否则 404，不泄露存在性）；本单实减额不得超过券面额；实减币种必须 = 券币种——违反即调用方算错，当场抛错回滚。
- **[CPN-37]** 支付成功核销：`markPaid` 事务内 LOCKED→USED（记 used_at）并写一条 USE 流水，金额取锁定那刻定格的实减额；本单没用券或重放（0 行）都是无副作用返回。
- **[CPN-38]** 付款前取消/超时关单走释放：LOCKED→UNUSED 且清空 order_id/locked_at/applied_discount_amount（与 DB CHECK 自洽），写 RELEASE 流水；只认 LOCKED，USED 的券永不通过释放回到可用（释放与补偿是两件事，混用会算不清「用过几次」）；释放幂等。
- **[CPN-39]** 释放/退券覆盖全部取消路径：买家取消、待付款超时关单、待发货超时自动取消共用 `cancelFrom` 单一落点，按真实前态分流（未付款→释放；已付款→USED 券走退券补偿）；支付失败不直接动券（订单留在待付款，靠上述两路收口，理由见 CPN-61）。
- **[CPN-40]** 状态与订单引用自洽由 DB 强制（ck_user_coupons_order_ref）：LOCKED 必 order_id/locked_at/applied_discount 齐非空；USED 必 order_id/used_at/applied_discount 齐非空；UNUSED/EXPIRED/VOID 三者必空——半份状态写不进去。
- **[CPN-41]** 过期收敛任务：每 10 分钟一轮、每批 500 张循环到刷完，只把 `UNUSED 且 expire_at<=now` 刷成 EXPIRED；LOCKED 的券不收敛（优惠已定格在订单上，不能因券过期让已下单的支付失败）；任务只为展示/统计/索引服务，券可用与否一律读时比 expire_at。
- **[CPN-42]** 核销流水 `coupon_usages` 是 append-only 账本：LOCK/USE/RELEASE/RETURN 每次动作一行（含券 id、订单、用户、店、动作、金额），永不更新；记的金额是<b>本单实际减免额</b>（锁定即定格、封顶后可能小于面额）而非面额，对账按流水。
- **[CPN-43]** 订单侧落三件券快照（`user_coupon_id` + `coupon_bearer` + `discount_amount`，列口径与 DB CHECK 见 ORD-24）：券规则会改、券会被停用，订单必须能自证「当时减了多少、凭哪张券」；减免额取**封顶后实减**（`applied_discount` 同值），不是面额。
- **[CPN-44]** `order_id` 单列承载「本券当前关联订单」，随状态换义（LOCKED=占用的单 / USED=核销的单），刻意不分 locked_order_id/used_order_id 两列（避免两个真相）；历史轨迹归流水。
- **[CPN-61]** 支付失败（confirm 失败）**不释券**——规则而非疏漏：confirm 失败后订单仍停留在待付款，若此刻即时释券（LOCKED→UNUSED），券回到买家口袋，而订单还挂着这张券的折扣快照；买家对同一订单重试支付成功时，核销走 `LOCKED→USED` 条件更新会命中 0 行（券已不在 LOCKED）——结果是**折扣生效了但券没被消耗**，同一张券还能在别的订单二次使用。因此待付款期间券必须保持 LOCKED，释券只由取消/超时关单两条路收口（CPN-38/39）。
- **[CPN-62]** 运营作废的执行入口（C7 转正，CPN-34 状态机里 VOID 那条边自此落地）：`POST /admin/coupons/{id}/void`（staff 域，204）。**一期只放 UNUSED→VOID**；LOCKED（被未付款单占用，先取消该单释放再作废）/ USED（已核销，逆向走退款退券）/ EXPIRED / VOID 一律 409 并逐类给可理解的 detail，券不存在 404——不新增 error code（status + detail 足够，无按码分支）；强行抽走 LOCKED 的券等于让已展示的成交价凭空变贵，CPN-34 里 `LOCKED→VOID` 那条设计边刻意未开。作废走 `status='UNUSED'` 条件更新做并发闸门（抢不到 0 行按 409 冲突报「状态已变化」）；不写 coupon_usages 流水（action 枚举无 VOID，作废也不是金额动作），留 `[COUPON] 运营作废` 结构化日志。

## 逆向退回（退款退券）

- **[CPN-45]** USED 不因退款逆转：走「补发一张同规则新券」的补偿（新行 `source=REFUND_RETURN`），原券保持 USED，流水记 RETURN——核销流水不断链、可算清一张券被用过几次。
- **[CPN-46]** 退券触发点三个，均与退款同事务：①已付款（PAID）订单取消（买家取消/待发货超时自动取消共用 cancelFrom 的 PAID 分支）；②售后「仅退款同意」；③售后「退货收货」退款落点。整单退款才退券；没用券的订单无副作用。
- **[CPN-47]** 已过期不退：退款时刻原券已过 expire_at → 跳过补发（券是限时权益不是资产）。
- **[CPN-48]** 补发新券规则：整份快照复制原券（名/门槛/面额/币种/承担方），新券窗口 = [now, 原券 expire_at]，不延长原有效期；模板已改/已停不影响（退的是同一张券的权益，不是重新发放）。
- **[CPN-49]** 退券不占发放名额、不恢复每人限领额度：部分唯一索引只约束 `source='CLAIM'`，REFUND_RETURN 不受限——既保证补偿插得进去，又防止「退款→再领」反复薅；对账上 CLAIM 是营销成本、REFUND_RETURN 是履约成本。
- **[CPN-50]** 退款绝不退券面额（否则等于给用户套现）；一期售后整单口径，部分退款按比例退券不做。

## 券包与前端展示

- **[CPN-51]** 券包「未使用」页签同时收 LOCKED（未过期）：对用户它就是没花掉的券（展示仍如实标 LOCKED=「结算中」），否则这类券三个页签都查不到、用户以为丢了；EXPIRED 页签收「已收敛的 EXPIRED ∪ 库里还 UNUSED 但已过 expire_at 的」。筛选按展示口径不按库列。**已知瞬时盲区**：LOCKED 且已过期（下单冻结后一直不支付、又跨过 expire_at）三签都查不到，但待付款窗口封顶 15 分钟（ORD-26），超时关单把券释放回 UNUSED 后 EXPIRED 页签就收得到；过期任务只扫 UNUSED、不碰 LOCKED 是同一取舍的另一面（口径见 CPN-41），不单独处理。
- **[CPN-52]** 券包行状态是读时算的展示状态：库里 UNUSED 但已过失效时刻 → 出参 EXPIRED；非法状态筛选值 400（合法值表即枚举 name：UNUSED|LOCKED|USED|EXPIRED|VOID）。
- **[CPN-53]** 券包每行带：店名（跨 schema 点查拼装）、orderId（未使用为 null，有则给「查看订单」链接）、来源徽章——REFUND_RETURN 必须明示「退款补发」（凭空多一张券没有解释会被当成故障）；状态标签「未使用/结算中/已使用/已过期/已作废」。
- **[CPN-54]** 券面只出三行：面额大字 / 一句话规则（「满 ¥X 减 ¥Y」，threshold=0 出「无门槛减 ¥Y」，不写「满 ¥0」）/ 店名+有效期区间；券模板名、承担方等字段上卡面即噪音，一律不展示；金额文案去无意义尾零（整元语义），走共享 `couponMoneyText` / `couponYuanText`（`packages/common/coupon.ts`）——这是 MONEY-11「展示只经 formatMoney」的唯一受控例外，且仍不裸算分、币种符号照查表。
- **[CPN-55]** 前端零重算：券能不能用、能减多少一律以后端评估结果为准（usable/discount/discountAmount 均为后端回显值），共享文案层不含任何业务判定；「已减 ¥X」取预览回显的券减免，不拿面额自减。
- **[CPN-56]** 商品详情页领券浮层：该店无可领券时整块不渲染；未登录点领取拉起全局登录 Dialog；soldOut 按钮文案「已领完」置灰；领撞 409 COUPON_ALREADY_CLAIMED 就地改标「已领取」（不当失败处理）；「已领取」是浮层局部状态、刷新即丢（匿名端点刻意无个人标记，一期不根治）。
- **[CPN-57]** 结算选券行文案：已选券 →「已减 ¥X」（后端值）；未选但有可用券 →「N 张可用，未使用」；无候选 →「本店暂无可用优惠券」且不开候选弹层；不可用券置灰且行内灰字写明原因（不只靠颜色）。
- **[CPN-64]** 券包行透出**时间类**可用性原因（C8）：`MyCouponResponse.unavailableReason` 取 NOT_EFFECTIVE（未开始）/ EXPIRED（已过期）/ null，判定复用结算评估器的同一时间口径（CPN-20/21 的 `CouponEvaluator.timeReason`，两处「为什么不能用」不许各写一份比较）。只对「还在手上」的展示状态（UNUSED/LOCKED）给出：过期未收敛的 UNUSED 展示状态本身已折叠成 EXPIRED（CPN-52），徽章即解释、不再挂原因；终态券（USED/EXPIRED/VOID）恒 null。门槛/币种原因需要结算基数，券包没有购物车上下文，**算不出也不硬算**（半套即全量，这是刻意边界不是遗漏）。卡片在有效期行下补一行灰字：未开始 → 生效时刻；结算中且已过使用时间 → 「本单之外不能再使用」。

## 鉴权与接口面

- **[CPN-58]** 端点鉴权划分：店铺可领券列表匿名（`/api/*` 通道）；券包/领券需登录；卖家三端点需登录 + COUPON_MANAGE；运营作废（CPN-62）在 staff 域，权限暂借 CMS_MANAGE（运营岗 OPS）——admin 域没有券运营专用码，独立授权点待 `docs/conventions/permission-codes.md` 增补后替换。结算预览/下单传 `userCouponIds`（可空）。券不存在与不属于本人都给 404（不泄露存在性）；不属于本人的券不在结算候选里，选用会走 400「所选优惠券不可用于本单」。
