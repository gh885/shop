# 售后 / 退款

> 代码入口：`apps/server/.../aftersale`（退款单、十态机、渠道执行与重试）；payment 的 `PaymentRefundCommand`；买家 `apps/web/src/order`，卖家 `apps/seller/src/order/refund`。规则以代码为准沉淀，改代码请同步本文件。

## 准入与窗口

- **[AFS-01]** 买家发起退款须同时满足：订单主状态为 `SHIPPED`（待收货）或 `COMPLETED`（已完成）、申请窗口未过（AFS-02）、申请到的每个订单行上都没有未完结退款单（AFS-03）。任一不成立 409「当前不可申请退款」；待发货（PAID）不给入口——那一段买家的出口是取消整单退款（ORD-20）。
- **[AFS-02]** 申请窗口：待收货期间随时可申；订单转 `COMPLETED` 时由完成时刻 +**15 天**回填 `apply_expire_at`（`OrderTimeouts.AFTER_SALE_APPLY`），此后按该截止时刻判。前端 `canApplyAfterSale` 与后端同一口径。
- **[AFS-03]** **同一订单行同一时刻至多一张未完结退款单**：硬闸门是 `aftersale.refund_lines` 的部分唯一索引 `uk_refund_lines_open_item`（`active AND line_type='ITEM'`），并发重复申请撞索引即 409。退款单到终态（已退款/已拒绝/已撤销）时把行标记 `active=false` 让位；失败单保持占位（重试期内仍算未完结）。
- **[AFS-04]** 被拒/撤销/已退款后，只要仍在申请窗口内，就可以就**还没退完的行**重新申请——退款是行级的，一单退掉部分商品不影响剩下的额度。
- **[AFS-06]** 退款单只能由订单归属买家发起/查看；非本人访问与不存在同为 404。
- **[AFS-43]** 待收货是买家唯一讲理的地方：包裹丢失、破损、拒收都应在这一段发起退款。**争议未决时自动确认收货让位**——`completeUnreceived` 读订单上的售后角标，`REFUNDING` 直接返回 false；退款落到终态、角标清掉后，同一轮扫描自愈。
- **[AFS-46]** 已付款订单取消 = 自动整单退款：order 发 `OrderCancelledEvent`，aftersale 同事务建 `REFUND_ONLY` 退款单（全部行 + 运费行），走「待处理 → 已同意 → 退款中 → 执行」。渠道失败时退款单停在「退款中」由重试线追，取消本身不回滚（买家的取消权优先）。

## 类型、行与申请内容

- **[AFS-08]** 类型三值：`REFUND_ONLY`（仅退款，退还没发出的货）、`RETURN_REFUND`（退货退款，退已发出、寄回的货）、`COMPENSATION`（补偿，货留买家只退钱）。买家入口只能选前两种；补偿由内部命令 `CompensationCommand` 发起。
- **[AFS-09]** **行级退款**：申请必须给 `lines: [{ orderItemId, quantity }]`，同一订单行一次只能出现一次。退款单行有三种：`ITEM`（挂订单行 + 数量）、`SHIPPING`（整单退满时的运费）、`COMPENSATION`（只退钱）。
- **[AFS-10]** 申请原因必选：`reasonCode` 取自枚举 `AfterSaleReason`（NO_REASON / QUALITY_ISSUE / … / OTHER），补充说明 `reason` 可选、最长 200 字，只给人看不参与判定。非法枚举值在请求体反序列化阶段 400。
- **[AFS-11]** 买家查看/操作退款只有一个入口——「最近一张退款单」（优先进行中的那张，否则最近一张含终态）；从未申请过时查询 404（语义为「没有」）。
- **[AFS-45]** 七天无理由强制（消保法第 25 条）：类型为退货退款、原因为 `NO_REASON`、距「收到商品」未过 7 天、订单每一行的无理由声明快照都支持——四条同时成立才在申请瞬间定格 `no_reason_enforced`。成立后卖家在待处理阶段只剩「同意」；按钮不下发 + 服务端硬校验双门。计时起点取签收时刻，未签收则取完成时刻，两者都没有则不成立。

## 金额

- **[AFS-12]** **金额服务端算**：行商品款 = `goods_paid_amount × 本次数量 ÷ 购买数量`，向下取整；该行最后一次退款退剩余额（保证 INV-13/14 收口）。客户端只报数量，不报金额。
- **[AFS-13]** **部分退款不退运费**；仅当本次退款后该子订单所有行 `refunded_quantity = quantity`（子订单全退）时追加一条 `SHIPPING` 行，金额 = 子订单 `shipping_fee`。运费单独成行，不被行金额上限拦下，也仍计入 `refunded_amount`。
- **[AFS-16]** 退款币种 = 订单币种；行账本与订单/主订单累计按同一币种写入。

## 状态机与时限

- **[AFS-17]** 退款单十态：`PENDING`（待处理）/ `AGREED`（已同意）/ `RETURN_PENDING`（待寄回）/ `RETURNED`（已寄回）/ `RECEIVED`（卖家已收货）/ `REFUNDING`（退款中）/ `REFUNDED`（已退款）/ `REJECTED`（已拒绝）/ `CANCELLED`（已撤销）/ `FAILED`（失败）。唯一真相：`aftersale.model.RefundStatus.TRANSITIONS`。
- **[AFS-18]** 合法转移：待处理→已同意/已拒绝/已撤销；已同意→待寄回（退货退款）或退款中（仅退款/补偿）；待寄回→已寄回/已撤销（买家）；已寄回→卖家已收货/已撤销（卖家确认拦截成功）；卖家已收货→退款中；退款中→已退款/失败；失败→退款中（人工重试）。表外转移一律 409。
- **[AFS-19]** 副作用由**类型**定：退货退款在「已退款」时回补库存（按退款行的数量，不是整单）；仅退款不回补；补偿不动库存。取消订单的库存回补归 order 的取消链，退款侧不重复回补。
- **[AFS-20]** 拒绝只从待处理（`PENDING`）：已寄回之后货已离开买家，卖家只能确认收货（退款）或确认拦截（已撤销、钱不出），不再有「验货不通过拒绝」这条边。
- **[AFS-21]** 每次转移用条件更新（`WHERE status = 前置态`）做并发闸门，抢不到行报 409。
- **[AFS-22]** 渠道调用不留时间线：每一次向渠道发起的退款落一条 append-only 的 `refund_executions`（成功与否、渠道退款单号、失败原因）。重试只追加记录，不改单据状态；状态只在确认最终结果时推进。
- **[AFS-23]** 三条超时线（`AfterSaleTimeouts`）：
    - 待处理超 **48 小时** → 系统自动同意（仅退款/补偿直接发起退款；退货退款进入待寄回）；
    - 待寄回超 **7 天**且从未登记回寄运单 → 自动关闭（`CANCELLED`）；
    - 已寄回超 **10 天**卖家未确认收货 → 自动确认收货并退款、回补。
      时间起点分别取 `created_at` / `agreed_at` / `return_registered_at`（后两者在 V85 才有，不用 `updated_at`——条件更新不触发自动填充）。扫描每 30 秒一批至多 100 笔，逐笔经 `Sweep.each` 隔离，无分布式锁，并发靠条件更新让位。
- **[AFS-47]** **退款重试**：渠道调用失败时退款单停在「退款中」，由 `RefundRetryJob` 每 30 秒扫「上次执行已过 1 分钟」的单再提交一次；每笔退款最多 3 次尝试（执行记录数），耗尽转「失败」等人工。渠道幂等键是退款单号（`out_request_no`），重试不会退第二次。
- **[AFS-48]** 失败单可由卖家「重试退款」重新发起（失败→退款中→执行）；它是自动重试耗尽后的唯一出口。

## 买卖家动作与权限

- **[AFS-25]** 买家可做：申请、撤销（待处理/待寄回）、回寄填单（待寄回，以及已寄回后卖家确认收货前均可改单号）、对终态重新申请。按钮吃售后单下发的 `availableActions`。
- **[AFS-26]** 卖家可做：同意（待处理，按类型分派）、拒绝（待处理，理由必填；无理由强制单不给）、确认收货（已寄回）、确认拦截（已寄回）、重试（失败）。操作端点挂在订单资源下（`/seller/orders/{id}/refunds`，按订单 id 定位最近一张进行中的退款单）。
- **[AFS-27]** 卖家动作与工作台要求 `ORDER_FULFILL`（与订单作业同权），店铺归属由 `X-Shop-Id` 圈定，越店 404。
- **[AFS-28]** 卖家工作台：本店退款单分页、`created_at` 倒序、status 可选筛选（空=全部，非法值 400）；默认停在「待处理」。
- **[AFS-29]** 决策弹窗在确认前按 orderId 重拉退款单（类型/原因/金额/退货运单号），按类型与状态明示后果；拉不到不拦确认，降级为提示。强制单在原因行挂「七天无理由，不可拒绝受理」徽章。
- **[AFS-30]** 拒绝理由必填（≤200 字），落 `refunds.reject_reason`，随买家详情下发；买家撤销无入参。
- **[AFS-40]** 动作集下发：按钮组唯一真相 = 后端算好的 `availableActions`（`RefundAvailableAction`）。买家口径：撤销/回寄/重新申请；卖家口径：同意/拒绝/确认收货/确认拦截/重试（正常推进在前、破坏性在后）。`AUTO_*` 超时动作不下发。卖家订单列表的行内按钮同样吃 `/seller/refunds/actions` 批查结果，不按订单上的角标另推。
- **[AFS-42]** 回寄地址由后端下发、买家详情唯一消费点：`RefundResponse.returnAddress` 在查询时经 shop :: api 实时解析默认退货地址，不做快照；null 表示卖家没配，前端提示联系客服但不挡登记。
- **[AFS-44]** 拒绝理由随买家详情下发（`rejectReason`，仅被拒时有值）；卖方详情/工作台不回填。
- **[AFS-41]** 回寄运单可重复提交覆盖：每次 `ReturnShipmentCommand.replace` 作废旧 RETURN 包裹及其轨迹后重建，退款单上的承运商/单号/登记时刻随之覆盖；「已寄回」后再提交只更新物流三列，不改状态。

## 逆向联动（资金 / 券 / 库存 / 订单账本与角标）

- **[AFS-35]** 退款成功经 payment :: api 提交渠道退款并累计 `payments.refunded_amount`（退满才转 `REFUNDED`，部分退款留在 `SUCCESS`）；渠道拒退不抛异常，退款单落一条失败执行记录并由重试线取舍。
- **[AFS-37]** 整单退满时同事务退券（`CouponCommand.returnOnRefund` 补发新券）；部分退款不动券。
- **[AFS-38]** 退货退款在退款成功时按退款行数量回补库存（`stock += n / 可用 += n`，流水 `RETURN`）；仅退款与补偿不回补。
- **[AFS-39]** 退款状态每变一次，aftersale 经 order :: api 写回**订单角标**与**主订单角标**（`NONE/REFUNDING/REFUNDED/COMPENSATED`，§5.4）；退款成功时同事务落行账本、订单/主订单已退额、履约重算与「全额退款关单」。订单不再保存「最近一张售后单状态」的列。
- **[AFS-50]** 行账本口径：仅退款 `settled_quantity += N`、`refunded_quantity += N`；退货退款 `shipped_quantity -= N`、`refunded_quantity += N`（结清量不变）。两条路径都按 `refunded_amount += 金额`，上限在 UPDATE 的 WHERE 里。

## 已知缺口

- **仅退款在当前窗口下几乎不可达**：申请窗口只开到待收货/已完成，而这两个状态意味着全部行已结清（`settled = quantity`），仅退款的「未发且未退」额度因此为 0（除非先取消过包裹）。丢件/拒收的正确流程是「先取消发货单，再按仅退款退」（§8），但取消后订单会退回待发货、窗口关闭。下一批需要二选一：放宽窗口（待发货/部分发货也允许仅退款），或在卖家同意时由物流按行取消未签收包裹。**在此之前，卖家对已发货商品的免退货诉求请走补偿命令。**
- 卖家端没有「按行取消包裹」的能力（`ShipmentService.cancel` 整张取消），部分数量的退款与部分取消组合尚无 UI。
- 补偿只有内部命令，没有运营后台入口；补偿上限只做了模型级「已退 + 已补偿 ≤ 实付」。
