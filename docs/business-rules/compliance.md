# 内容合规（违禁词闸门）

> 代码入口：`apps/server` compliance 模块（`ForbiddenWordCommand` / `ForbiddenWordService` / `ForbiddenWordMatcher` / `compliance.forbidden_words`，V73）、消费点 `ProductService` 的发布门槛与 `updateBasic`、卖家端 `apps/seller/src/product/forbidden-word.ts`。规则以代码为准沉淀，改代码请同步本文件。

## 闸门管什么、在哪个时机管

- **[COM-01]** 公开文本在**两个**时机过闸：① 发布 / 重上门槛（`ProductService.ensurePublishable`，与「标题非空」同一道门）；② **非草稿态**改公开文本即时过闸（`updateBasic`）——只在发布时拦是不够的，「先上架、再把标题改成违禁词」正好绕开那道门。草稿态放行：卖家要先能把内容填进草稿，要拦的是**公开可见**那一刻。命中一律 400 + code `FORBIDDEN_WORD_HIT`，**没有 WARN 放行分支**——宁可误杀一次让卖家改文案，也不做「先上架后清理」（后者等于没有闸门）。今天受管的公开文本是商品标题与卖点两处；详情的落库形状是图片 key 数组，没有自由文本可判。
- **[COM-02]** 判定是**同步命令而非事件**：闸门必须在写入方自己的事务里裁决，所以 `ForbiddenWordCommand` 是 compliance :: api 对外唯一的命令，product 在 `allowedDependencies` 显式登记。「先写后异步扫」意味着违规文本已经公开过（哪怕秒删），那是事后补救不是闸门；不过闸则该次写入一起回滚，不存在「商品已上架但内容没过闸」。判定本身只读（service 侧 `Propagation.SUPPORTS` + 缓存），因此能不能真回滚取决于调用方是否在事务里——需要「不过闸就回滚」的发布路径都在事务里。

## 命中口径

- **[COM-03]** 只做**归一后的子串命中**，不做正则 / 通配 / 分词 / 上下文豁免：那会把误杀面放大到不可预期，而误杀一个正常卖家的代价（申诉、客诉）远高于漏放一个灰词。归一 = NFKC 折叠全半角与兼容字符 + 转小写 + 去掉零宽字符，所以词表写「１００％」也能被标题里的「100%」命中，卖家用全角或夹零宽绕不过去。口径全部收在纯函数 `ForbiddenWordMatcher`（不碰 DB、不碰 Spring，可直接单测）：一旦分散，「商品过闸」与「评价过闸」就会慢慢长成两套判定，运营改一次词表要改两个地方。词表 `word` 列存**原样**不做归一——改归一规则不用迁移数据。
- **[COM-04]** 分类（`AD_LAW` / `FRAUD` / `PORN` / `POLITICS` / `INFRINGEMENT` / `OTHER`）**只用于给卖家一个可行动的提示，不参与命中判定**（同一列不做两件事：「标题含广告法违禁词」比「标题含违禁词」有用）。提示只带**第一个**命中词与它的中文分类标签——多词会把消息拉长，卖家改第一个再提交自然看到下一个。枚举名与 V73 的 `ck_forbidden_words_category` CHECK 是同一组值，加值要同时改两处。

## 词表与缓存

- **[COM-05]** 词表是**数据不是配置**：独立 schema 的一张 `compliance.forbidden_words`（word / category / enabled），运营增删改一行即生效、不用重启（塞进 `application.yml` 就得改配置重启）。`word` 全表唯一（人工维护最容易犯的错就是重复登记，由唯一索引挡掉）；停用一个词 = `enabled = false`（与删行同效，但保留行便于临时静音而不丢历史）。闸门每次要的是**整集**：一次 SELECT 读完在内存匹配，换掉「一次写入做 N 次查询」。本轮 `ForbiddenWordMapper` **刻意只读**（闸门的正确性依赖「词表不会被业务写入悄悄改掉」），词表随 V73 迁移种子。读带 60s TTL 的单槽缓存，刷新时整体换掉——读侧要么看到旧的完整集、要么新的完整集；口径是「运营改词表一分钟内生效即可」，不做强一致。
- **[COM-06]** 词表**不下发前端、前端不做本地判定**：抄一份就会与后端漂移（运营下线某个词，前端还在拦一个已经合法的标题）。卖家端只消费 400 那一发——按 `FORBIDDEN_WORD_HIT` 分支，从 detail 里锚定「句首的字段名」与「『包含违禁词』后面的那个词」，把错误标到对应输入框并给出命中词；锚定失配时退化成全局提示，**不硬猜字段**（误报到别的字段比不报更糟）。
