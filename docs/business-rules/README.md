## 编号约定

- 编号只标**首次收录**，跨域联动条款归「动作的发起方」文件（例：退券细则归 coupon.md，aftersale.md 只留一句联动）；引用时可跨文件直接写编号。
- 条目缺号（如 LOG 缺 05/08、PAY 缺 16~~21/29~~31/35/39/40）表示该条已合并进其他条款、移交到归属域文件，或整条属实现细节而非业务规则，不回收号、不重排——保持历史引用稳定。
- `Xxx-N`（CPN-N1…）与文件末「已定案未实现」节：已拍板但代码未落的规则，落地时转正、废弃时删除。

## 已知留白（不是遗漏）

- 券的自动促销半边引擎、叠加字段、事件发券幂等均未落（coupon.md 未实现节）。
- 封号/作废的管理端点已落（ACC-71、CPN-62），但 admin 侧无列表查询端点，运营页面缺位（TODO.md「admin 运营入口」行）。
- 店铺停营业**不级联券**：店被驳回/禁用时，该店券模板与其下用户券保持原状（ACC-72 只管商品与成交闸门，下单侧的营业闸会让券用不出去）。要不要随店停发/作废未拍板。
- `ShopStatus.DISABLED` 的写入方只有「店主注销连带停营业」一条（ACC-76），平台侧封店端点仍缺（ACC-60）——封禁落地前级联下架覆盖「审核驳回 + 店主注销」两条路。
- 注销只是**交还手机号**：号码维度的历史计数（如 ORD-59 那类按号码的额度）随匿名化归零，重新注册的同号码是新主体、拿满额（ACC-77），与「买家滥用侧无计数」同档，属已接受。
- JWT 密钥是否补长度/存在性闸门未拍板（ACC-73 记的不对称现状）。
- 号码明文索取只有留痕、**没有频次闸门**：卖家逐单取买家电话（ORD-62）、平台逐条取店主号、成员逐条取他人号（ACC-79）三个出口都是脚本刷全量在今天仍然可行，只是每一笔都留得下痕——相对改前「一屏列表全是明文」是净改善，闸门与到期回落等接消息/客服体系或隐私面单时一起补。
