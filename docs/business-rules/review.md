# 评价（商品评价 / 追评 / 卖家回复）

> 代码入口：apps/server/src/main/java/com/shop/platform/review；apps/web（商详评价区、订单评价入口）、apps/seller（订单评价与回复）。规则以代码为准沉淀，改代码请同步本文件。

## 一、评价主体与口径

- **[REV-01]** 一单一评：评价挂在**订单**上（订单本身即单店单，orders 按店拆单），一个订单至多一条评价，由部分唯一索引在 DB 层兜底并发。评价不可修改、不可删除（append-only 账本语义）。
- **[REV-02]** 按商品行评价：评价含 N 条**评价行**，每行对应订单的一个订单行（`order_item_id`），逐行给「星级 1~5 + 文字 + 图片」。提交时必须覆盖该订单的**全部**订单行，缺行按 400 拒——半份评价会让好评率的分母与分母口径都说不清。
- **[REV-03]** 可评价时点：订单主状态为 `COMPLETED`（确认收货或超时自动收货）之后，且评价窗口为完成时刻 +**30 天**（`review.service.ReviewWindows.FOLLOW_UP_DAYS`，窗口由 review 域自己算，order::api 只给完成时刻）。窗口过期未评即视为放弃，不做「超时默认好评」——默认好评会把「没评价」和「给了好评」混成同一个信号，商品页的好评率就不再可信。
- **[REV-04]** 只能由订单归属买家本人评价，非本人一律 404「订单不存在」（不泄露单据存在性，ORD 越权口径）。已评价的订单再次提交按 409「该订单已评价」。
- **[REV-05]** 评价里的商品信息（名称/图）取下单快照，商品下架/改名不影响历史评价展示；评价不复制价格与金额（金额在订单里，评价不是对账凭据）。

## 二、内容与图

- **[REV-06]** 星级 1~5 必填（DB CHECK 同词表）；文字可空（只打星也算一次评价），有文字时上限 **200 字**（与 `NoteFieldRules.FREE_TEXT_MAX` 同一档「一段人写的说明」）。文字按纯文本存与出，不解析 HTML。
- **[REV-07]** 每条评价行最多 **3 张图**，图片是对象存储 key（与商品图同一口径，存 key 不存 URL），单 key ≤255；传完整 URL 一律 400——存 URL 会让外链图片永远挂在别人的服务器上。
  **当前只有后端这一半**：买家端还没有上传通道（`/seller/**` 的图片凭证端点带店铺上下文，买家拿不到），
  所以商详评价区能展示图、提交表单暂时只收星级与文字。图这一格等买家上传通道落地再开前端入口，
  契约与存储早就是它该有的形状，届时前端不用改契约。
- **[REV-08]** 图与文字都只作展示：不做敏感词检测、不做审核流（违禁词检测仍是 [taobao-comparison](taobao-comparison.md) 里的 P1 差距项）。追评同理。

## 三、追评与回复

- **[REV-09]** 追评一次：买家可在评价提交后追评一条（纯文字，≤200 字，不可再追）。追评不参与好评率统计（好评率按首次评价的星级算，追评是补充说明不是二次打分）。
- **[REV-10]** 卖家回复一次：店铺成员（OWNER/MEMBER）对本店订单的评价可回复一条（≤200 字），回复不可编辑、不可删除；非本店成员对这条评价一律 404（归属闸门口径同 ORD-01）。回复由谁发出记 `reply_by`（店铺成员 user id），仅作留痕，不进买家可见内容。
- **[REV-11]** 追评与回复互不阻塞：买家追评后卖家仍可回复，卖家回复后买家仍可追评（各一次）。

## 四、查询与展示

- **[REV-12]** 商品评价区（商详页）：`GET /api/reviews/products/{productId}` 返回该商品的评价列表（每行商品名快照、星级、文字、图、追评、卖家回复、时间、买家昵称掩码形态）与聚合（评价条数、平均星级、好评率）。好评率 = 首次评价星级 ≥4 的行数 / 全部行数（追评不计入），保留一位小数；无评价时聚合各项为 0 而不是 null。
- **[REV-13]** 评价列表排序：首次评价时间倒序，同时间按 id 倒序（稳定）；分页走 `PageParams`。
- **[REV-14]** 聚合与列表同一次查询口径：聚合按**当前筛选之外的全量**算（不受分页影响），列表按分页切片；两者不是一个 PageResult 的两半，避免「翻到第二页好评率变了」。
- **[REV-15]** 买家昵称在评价里恒为掩码形态（前 2 后 2，中间 `***`）：评价列表是公共出口，明文昵称只经买家自己的订单评价页可见（那里也是同一个掩码口径，不给明文出口——一期不做「看买家昵称」这件事）。

## 五、留痕与门禁

- **[REV-16]** 评价提交/追评打结构化事件 `review.created` / `review.appended`（字段 `review_id` / `order_id` / `user_id` / `item_count`），卖家回复打 `review.replied`（`review_id` / `shop_id` / `operator_id`）；目录见 [business-event-logging.md](../conventions/business-event-logging.md)。
- **[REV-17]** 评价不是治理动作，**不进操作审计账本**（`audit :: api`）：买家与卖家之间的内容往来不属于「平台谁对谁做了什么」，混进去会让审计查询被无关行淹没。
