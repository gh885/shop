# 商品 / 类目 / 库存

> 代码入口：apps/server/.../product、inventory；apps/seller/product、apps/web/products。规则以代码为准沉淀，改代码请同步本文件。

## 一、类目树

- **[PRD-01]** 类目树固定最多 3 级：新建类目 level 由父级推导（根 = 1，子 = 父 + 1），超过 3 级直接拒绝（"最多支持三级类目"）。根节点 parent_id 用零 UUID（ROOT_PARENT_ID）占位而非 NULL。
- **[PRD-02]** 在有启用父级下才能创建子类目：父类目不存在拒绝；父类目已禁用拒绝（"父类目已禁用，不能在其下创建"）。
- **[PRD-03]** 同级类目名唯一（≤64 字，入库前 trim），并发重名由唯一索引 uk_categories_parent_name 兜底为 409。
- **[PRD-04]** 类目创建后不允许移动（parentId 不可改），更新接口只能改名称/排序/图标。
- **[PRD-05]** 类目不物理删除，只有启用/禁用两态；禁用采用查询侧裁剪、不写扩散，可无损恢复。
- **[PRD-06]** 禁用级联口径是"父级不可见则整支剪掉"：前台类目树（GET /api/categories/tree）与子树展开 descendantIds 都只走启用节点，父链上任一节点禁用，其后代整体不可见；管理端树（/admin/categories/tree）含禁用节点。
- **[PRD-07]** 禁用闸门按**全量子树**统计（含自身、含禁用分支）：子树内仍有商品引用（含草稿、下架——所有状态的商品都算）即拒（400 人话 detail「该类目或其子分类下仍有 N 个商品，移出后才能禁用」，无 code——GEN-19 第③条线，service 层自判）。为什么不能只数挂在这个 id 上的商品：商品只挂三级叶子，对一级/二级类目直挂引用恒为 0，闸门等于永不生效。为什么展开时不掺启用过滤（与 PRD-06/PRD-09 的 `descendantIds` 刻意不同一条口径）：召回侧那条问的是「买家此刻可达哪些」，这条问的是「这次禁用会波及谁」——子树里已禁用分支下的商品同样在这个类目治下，禁祖先不会让它们更可见，也必须一并移走。启用（→ACTIVE）不设闸门，随时可恢复。
- **[PRD-08]** 类目树同级排序规则：sort 升序，再按创建时间升序。
- **[PRD-09]** 按类目召回时子树展开（tab 可指一级类目、商品挂三级）；未知或已隐藏类目返回空集，召回侧按空流处理，不 404（脏 tab 不把首页打成错误页）。类目表全量内存展开，展开结果按类目 id 进 Redis 读缓存（`product:category-subtree`，前台类目树另存 `product:category-tree`）——feed 每刷一次就是一次全表读，缓存的是那次读；三个后台写各挂失效，改名/禁用下一请求即影响召回（见 apps/server/AGENTS.md「读缓存」）。

## 二、类目属性模板（规格 / 参数的定义）

- **[PRD-10]** 属性模板只允许挂在叶子类目（level=3），非叶子拒绝（"只有叶子类目（三级）才能挂属性模板"）。模板不下沉继承父类目。
- **[PRD-11]** 属性分两类且创建后不可互转：SPEC 销售属性（参与 SKU 生成）/ PARAM 非销售参数（仅展示）；改 kind 会让存量 SKU 失去出处，更新接口忽略 kind。
- **[PRD-12]** 属性默认值：required=false、allowCustom=true（卖家可扩充值域）、allowImage=false、sort=0；属性名 ≤32 字，同类目重名 409（uk_category_attrs_category_name）。
- **[PRD-13]** 属性禁用同类目语义：查询侧裁剪不写扩散——存量商品/SKU 快照自洽仍可见，禁用后新规格选择不再受理（updateSpecs 校验"规格属性已禁用"）；公开模板（卖家发布页/买家详情页）只出启用属性，管理端全量。
- **[PRD-14]** 属性值是规格的身份：valueId 全局作身份，同属性内值文本（≤64 字）唯一（uk_category_attr_values_attr_value）；来源分平台预置（PLATFORM）/ 卖家扩充（SELLER）。
- **[PRD-15]** 规格值第一版不支持删除，只支持改名/排序/改图；改名在同一事务内刷新所有引用 SKU 的 attributes/name 快照——spec_key 不动、SKU 身份不变、价格库存不丢（"改名不丢价"）。
- **[PRD-16]** 卖家提交值域外新值（customValues）时自动建档为 SELLER 来源值，同名复用（含命中平台预置值也不改其 source），upsert 一条语句落库；allowCustom=false 的属性拒绝值域外值。
- **[PRD-17]** 商品参数（params）模板校验规则：类目存在启用 PARAM 模板时——提交的每条参数必须带模板内 attrId（"参数必须关联类目模板属性"）、required 参数必须有值、allowCustom=false 且值域非空时值必须在值域内；类目无 PARAM 模板时维持自由文本（attrId 可为 null）。名称 ≤32、值 ≤64 字。建草稿与改基本信息两个入口都过这道校验；改基本信息未传 params 时用存量对有效类目复检。

## 三、商品（SPU）与草稿

- **[PRD-18]** 商品创建即草稿（DRAFT）：只落基本信息，specs=[]、无 SKU、价格区间为空；shopId 由店铺上下文（X-Shop-Id + 成员校验）注入，不由前端传入；创建必过类目挂载闸门（[PRD-82]）。
- **[PRD-19]** 商品标题上限 30 字（`ProductFieldRules.NAME_MAX`，创建/编辑两个 DTO 共用同一常量与同一句话术，GEN-52；入库前 trim）；草稿阶段允许空名（落空串满足 NOT NULL），发布（无论上架还是入库）时必须非空（"请先填写商品标题再发布"）。非空判定只有一处：`ProductService.ensurePublishable`——publish 与重新上架 `on()` 共用（此前标题门只挂在 publish 上，「发布→下架→清空标题→重新上架」能把无名商品放上线，PRD-43 的复检漏了它，已修并配 `ProductIT.下架清空标题_重上架复检标题门槛`）。
- **[PRD-20]** 一句话卖点（subtitle）要么不填/空串清空，要么 10~30 字（`ProductFieldRules.SELL_POINT_PATTERN` = `^$|^[\s\S]{10,30}$`，含同一句提示文案；用 Pattern 而非 `@Size(min)` 正因为空串要放行）；空串=清空、null=不改（PATCH 语义区分）。
- **[PRD-21]** 商品图片（mainImage/images/detailImages）存对象存储 key（非完整 URL），单张 key ≤255 字；详情图为按序铺开的图片流，代替富文本（无 HTML、无 XSS 面）。图片经卖家端申请票据（/seller/products/image-ticket）直传对象存储 product/ 前缀后回填 key。
- **[PRD-22]** 基本信息（标题/卖点/图片/参数）任何状态可编辑、在售实时生效（PATCH：null 不改）；但改类目是结构性操作——只有草稿可改，上架/仓库中商品换类目直接 409（"只有草稿可以修改类目，上架/仓库中商品请先下架"）。
- **[PRD-23]** SPU 改名（name 实际变化时）同事务重刷全部存量 SKU 的显示名快照（组合不变、只重拼字符串，价格/库存/spec_key 不动），使购物车/订单/列表不留旧标题。
- **[PRD-24]** 商品只支持单主分类（挂一个 categoryId），多分类需求出现时再拆关联表。
- **[PRD-84]** 七天无理由是 SPU 上的一项**服务声明**（`product.products.seven_day_return`，NOT NULL DEFAULT TRUE，V63）：法定默认支持，唯一关掉它的入口是卖家上新/编辑「基础信息」里那个勾选框（默认勾上）。为什么挂 SPU 而不挂类目——平台侧没有可运营的「特殊类目名单」界面，类目级默认会是个没人能改的死开关；挂 SPU 让每个商品自己声明，代价是新商品继承的是列默认值而非类目口径（将来真要做类目默认名单，从这条往下派发即可，不改语义）。声明只管**之后**下的单：下单时随 name/price/image 一族快照进订单项（ORD-61），售后判定读快照（AFS-45），卖家事后改勾选抹不掉已成交的权利。买家侧落点是详情页服务承诺那一行——支持写「7天无理由退货」，不支持就明写「本商品不支持七天无理由退货」：法定除外类目要的是**明示**，不吭声等于把披露责任推给买家眼神。
- **[PRD-25]** 商品归属店铺后不可变更；卖家一切读写都以 X-Shop-Id 圈定归属（requireShopOwned），非本店商品按不存在处理（404）。
- **[PRD-82]** 商品类目挂载闸门（`requireMountableCategory`，创建与草稿改挂同一道，不区分入口）：目标类目必须存在、是叶子类目（level=3，非叶子 400 + code `CATEGORY_NOT_LEAF`）、自身启用且父链上任一祖先启用（任一禁用 400 + code `CATEGORY_DISABLED`）——与公开类目树「父级不可见整支剪掉」同口径，防止商品挂进买家不可达的类目；判定顺序取「自身禁用 → 非叶子 → 父链禁用」，自身禁用是最致命的原因先报。

## 四、规格与 SKU 生成

- **[PRD-26]** 规格选择按类目模板属性（kind=SPEC）提交：属性不得重复；每个属性必须存在、启用、属于商品当前类目；每个维度至少选一个值（valueIds 与 customValues 至少一非空）；规格值必须属于该属性（重复选择自动按 valueId 去重）。
- **[PRD-27]** 规格规模上限：单商品规格维度 ≤10；每维度 valueIds ≤20、customValues ≤20（自定义值文本 ≤64 字且非空）；笛卡尔积组合总数 ≤500，超限拒绝（"规格组合数过多…请精简规格后重试"）。
- **[PRD-28]** SKU 身份 = spec_key：各维度 valueId 按模板顺序以 ':' join；无规格商品 specs=[] 恰好生成 1 个隐藏 SKU，spec_key 为空串；同商品组合唯一（uk_skus_product_spec_key）。
- **[PRD-29]** SKU 显示名公式：SPU 名 + 各规格值文本空格连接（如「iPhone 15 Pro 256G 黑色」），无规格即 SPU 名本身，超 160 字截断（skus.name VARCHAR(160)）。
- **[PRD-30]** 改规格按 spec_key 对账，三种归宿：组合没变的 SKU 原样保留（价格库存不丢，顺带刷新 attributes/name 快照）；新增组合即时创建（状态 ON_SALE、未定价）；消失的组合只置 DISABLED 停用保留，不物理删（SKU 是经营资产；在途订单裸引用不悬空；卖家重新选回时价格库存还在可直接复售）。
- **[PRD-31]** 上架（PUBLISHED）商品规格冻结：价格/库存/标题图片可改，规格组合不可改，PUT /{id}/specs 对上架商品 409（"上架商品不能修改规格，请先下架"）；草稿与仓库中可改。
- **[PRD-32]** 新生成的 SKU 同步创建库存主体行（stock=0、frozen=0，幂等建行）；"无库存行"一律按无货（0）处理。停用 SKU 的库存行原样保留（在途订单的冻结/释放依赖它）；只有放弃草稿时才物理删除 SKU + 库存行。
- **[PRD-33]** SKU 业务编码 skuCode（≤64 字）供仓管/ERP 对账：可空、全局唯一（uk_skus_code，多个 NULL 不冲突），重复 409；买家侧响应刻意不含 skuCode/status 等内部字段。
- **[PRD-34]** 卖家批量更新 SKU（PUT /{id}/skus）任何商品状态都允许（补货/改价/停用是日常运营）：price 与 stock 必填、其余字段 null 不改；SKU 必须属于该商品否则拒绝。
- **[PRD-35]** SKU 状态与缺货正交：ON_SALE 在售 / DISABLED 停用（"这个卖法不卖了"），缺货是售罄态不设状态；SPU 与 SKU 状态正交（一个上架 SPU 可含停用 SKU）。

## 五、价格

- **[PRD-36]** 价格全链路 Money {amount(分), currency}：入参出参同口径，非平台币种（一期仅 CNY）在入参即 400，DB 层 CHECK (currency='CNY') 兜底；售价与划线价均不得为负（CHECK price/original_price >= 0），且划线价不得倒挂低于售价（CHECK original_price IS NULL OR original_price >= price，ck_skus_original_price_ge_price，V62；存量倒挂行迁移时清空划线价抹平）。
- **[PRD-37]** 草稿期 SKU 允许未定价（price NULL）；发布 / 重新上架的门槛是每个在售 SKU 都已设价（"所有在售 SKU 都需设置价格后才能发布"），停用 SKU 不计入门槛也不被索取价格。
- **[PRD-38]** SPU 的 minPrice/maxPrice 是刻意冗余的聚合副本（真实成交价只认 skus.price），只统计在售且已定价 SKU；全部未定价时两端为 null；在发布、改规格、改 SKU 时同事务重算回填。价格排序/列表"¥xx 起"消费的就是这对副本。
- **[PRD-39]** 划线价（originalPrice）可空=不画删除线；传 null 表示不修改。不变式「划线价 ≥ 现价」在 SkuService.updateSkus 前置校验给友好 400（"划线价不能低于现价…"，无 code，不冒 500/撞 DB CHECK）：比的是「本次提交的现价」与「划线价终值」——划线价终值 = 本次提交值，未提交则取存量划线价（只抬现价抬过存量划线价同样被拦）；相等合法；SKU 不属于该商品时不抢跑，由归属校验报「SKU 不存在或不属于该商品」。

## 六、上下架状态机与可见性

- **[PRD-40]** SPU 状态机只有三态四转移：DRAFT→PUBLISHED（发布=立即上架）、DRAFT→WAREHOUSE（发布=放入仓库）、WAREHOUSE→PUBLISHED（重新上架）、PUBLISHED→WAREHOUSE（下架）；无其他路径，不物理删除商品。
- **[PRD-41]** 发布/上架/下架/重上一律条件更新乐观锁（WHERE status=源态，影响行数 0 即并发下状态已变，409 "商品状态已变化，请刷新后重试"）。
- **[PRD-42]** 发布门槛两档：目标为上架或仓库都要求"标题非空 + 每个在售 SKU 已设价"；只有立即上架另要求"至少一个在售 SKU 总库存 > 0"——仓库中允许售罄入库（对齐"架上商品不能全 0"）。此处「有货」量纲是**总库存 `stock`**（含被别单冻结的量），与交易闸门的**可用量 `stock − frozen_stock`**（PRD-71）刻意两口径：上架问「店里有没有这批货」，下单问「此刻还卖不卖得出去」。
- **[PRD-43]** 重新上架（WAREHOUSE→PUBLISHED）复检上架全部门槛（发布门槛 + 有货），下架期间 SKU 被改成全售罄/全未定价时挡住。**标题也在复检之列**——门槛判据是 `ensurePublishable` 一处、publish 与 `on()` 共用：标题门曾只挂在 publish 上，「发布→下架→清空标题→重新上架」因此能把无名商品放上线（PRD-19/42 都不允许），已修并配 `ProductIT.下架清空标题_重上架复检标题门槛` 钉住。
- **[PRD-44]** 上架商品保存 SKU 时预检"本次更新后仍至少一个在售 SKU 有货"（同 PRD-42 的总库存量纲）：把上架商品存成全部在售 SKU 库存 0 直接 409（"上架商品的库存不能全为 0，请先下架商品或补充库存"）；本次将置停用的行不参与判定，单行售罄、SKU 级停用仍允许。
- **[PRD-45]** 下架即"删除"语义（可无损恢复）；物理删除入口只有"放弃草稿"，且仅 DRAFT 可用（上架/下架商品是经营资产），放弃时同事务先清库存行再删 SKU 再删 SPU。
- **[PRD-83]** 店铺停止营业的级联下架（product 侧执行，闸与依赖口径见 ACC-72）：监听 `shop::events` 的 `ShopTradingSuspendedEvent`（同步 `@EventListener`，跑在店铺状态推进的同一事务里），一条条件 UPDATE 把该店全部 `PUBLISHED` 商品置 `WAREHOUSE` 并刷 `updated_at`。三条边界：① **只动在架**——草稿与「仓库中」原样不动，目标态与卖家手动下架一致，买家侧因此天然收不到（PRD-46 的列表/详情闸门不必为停营业另开口子）；② **不逐个走 `ProductService#off`**——那条路径带 X-Shop-Id 归属校验与读-改-写，是卖家语境专用（`off` 已收为 package-private，级联不借用）；③ **反向不回上架**——恢复 ACTIVE 不发布事件也不补逻辑，恢复营业 ≠ 平台背书这批历史商品仍满足上架门槛，卖家自己在后台重上、重上时复检 `ProductService#on`（PRD-43）。product 没有 events 包，下架对外不外泄事件，与手动下架同一条静默路径。
- **[PRD-46]** 买家侧可见性：列表接口只返回 PUBLISHED 商品，status 写死于服务端、不接受前端指定（否则草稿可被枚举）；详情非上架一律 404（不泄露"存在但没上架"）；买家 SKU 集合只返回 ON_SALE（停用卖法对买家不存在）。
- **[PRD-47]** 卖家工作台列表覆盖全状态（上架中/仓库中/草稿页签，默认上架中），每行带总可售库存与累计销量；操作权限：写读要求 PRODUCT_MANAGE（读随写权），类目及模板维护要求 CATEGORY_MANAGE。页签文案就是列表徽章文案（`PRODUCT_STATUS_META` 派生，不再抄一份「在售」）——「在售」在本仓库是 SKU 级概念（PRD-35 的 ON_SALE），SPU 状态从来没有这个词。
- **[PRD-48]** 销量口径：只计已完成订单（确认收货/超时自动收货）的行项件数，订单完成时同事务经 product::api 累加投影列 sold_count；待付款/取消不计、退款不回冲（V1 纯加总）；商品已删除时累加静默落空不报错。

## 七、库存模型、扣减与回补

- **[PRD-49]** 库存唯一真相源在 inventory.sku_stock：一 SKU 一行（sku_id 唯一），三量 stock（总库存/物理货量）、frozen_stock（已下单未扣实的冻结量）、可用 = stock − frozen_stock；product.skus 不再持有任何库存列。DB 不变式：stock≥0、frozen≥0、frozen≤stock。
- **[PRD-50]** 扣减时机 = 下单冻结、支付扣实：创建订单（转待付款）时同事务按行冻结（frozen += n、可用 − n、stock 不变）；支付成功才扣实（stock − n 且 frozen − n，货真的没了）。下单时不扣总库存，未付款不损失存量。
- **[PRD-51]** 超卖防护：冻结/扣实/释放全部是「WHERE 闸门 + RETURNING OLD/NEW」的条件更新单语句（行锁下原子判 可用≥n / 冻结≥n），无行返回即闸门未过——冻结不足抛 409 error code INSUFFICIENT_STOCK 并令整笔下单事务回滚（多 SKU 任一不足则全单失败）。
- **[PRD-53]** 回补按付款状态分流（取消唯一落点 cancelFrom，取消合法前态 = PENDING_PAYMENT / PAID）：未付款取消或待付款超时关单 → RELEASE（frozen − n、可用 + n，总库存不变）；已付款取消（含买家付款后取消、待发货超时自动取消+退款）→ RETURN 回补总库存（stock + n、可用 + n，幂等不依赖冻结状态）并同步留退款单据。
- **[PRD-55]** 库存流水是 append-only 账本：每笔变更记一行（FREEZE/CAPTURE/RELEASE/RESTOCK/RETURN），quantity = 总库存增量（FREEZE/RELEASE quantity=0 只换冻结归属；CAPTURE −n；RESTOCK/RETURN +n），前后帧（before/after 的 stock 与 available）来自更新语句 RETURNING OLD/NEW，严格连续可重放；只插不改，撤销用新行表达。FREEZE/CAPTURE/RELEASE/RETURN 必带 order_id，后台补货为 NULL。
- **[PRD-56]** 批量库存操作全局锁序：单批内按 skuId 升序逐行上锁；多店拆单按 shopId 升序成组、逐店冻结——固定全局顺序（shopId, skuId）杜绝反向顺序的两笔并发订单循环等锁死锁。
- **[PRD-57]** 后台绝对量调整（卖家把 SKU 总库存 set 成某值，读-改-写）走 @Version 乐观锁：并发调整冲突 409"库存已被其他操作修改，请重试"；新总量不得低于当前冻结量（在途订单占着），否则 409"总库存不能低于当前冻结量 N，请先等在途订单完成"（DB CHECK frozen≤stock 兜底）。补货接口为增量 stock += n（n≥0，不设闸门）。
- **[PRD-58]** 删除 SKU 的库存行有闸门：frozen_stock > 0（有未完成订单占用）拒绝删除（"该规格有未完成订单占用库存，暂不可删除"）——行没了之后取消/关单的 release 无处可释放；行不存在幂等返回。
- **[PRD-61]** 跨模块库存契约：读只有按 skuId 批查（StockReadQuery，返回 stock/frozen/available 三量），缺行不在 Map 中、消费方按 0 处理；写只有同事务同步命令（StockCommand），失败抛异常回滚调用方事务——不提供异步/最终一致通道。

## 八、搜索 / 列表 / 浏览

- **[PRD-62]** 买家商品列表筛选：categoryId 与 feed 召回同口径——经 CategoryService.descendantIds 展开**启用子树**后按 IN 匹配（tab/筛选可指一级类目、商品挂三级叶子；父链上任一节点禁用即整支不可见），未知/禁用类目得到空集、直接返回空页 total=0，不报错不查商品表（禁用不查挂载类目自身，父级禁用同样挡，与 [PRD-06]/[PRD-82] 同一条级联口径）；shopId 精确匹配、keyword 对商品名 LIKE 包含匹配（≤128 字、trim 后为空视为无关键词）；都不传 = 全站上架商品按新品排。
- **[PRD-63]** 买家列表排序白名单：newest（默认，createdAt 降）/ price_asc（按 minPrice 升）/ price_desc（按 maxPrice 降），词表与分支由 `ProductSort` 一处持有（wire 值 = 小写名，`fromWire` 解析，GEN-52）；价格排序直接吃 SPU 冗余价格副本免查 SKU 表。非法 sort 值 **422**（门在 DTO 的 @Pattern 上，GEN-19 第①条线，`ProductControllerTest.非法排序_422带字段名` 实测——原写 400 是未验证的推断）。每种排序都追加 id 降序兜底，保证翻页同值行顺序稳定不重复。
- **[PRD-64]** 分页契约：page ≥1（默认 1）、size 1~100（默认 10）。
- **[PRD-67]** 买家侧不拼店铺名、跨模块各取各的：商品响应只给 shopId，前端另查店铺详情；商品卡价格取 minPrice（"¥xx 起"）。
- **[PRD-68]** 销量展示文案唯一出口 `formatSoldText`（首页 feed、推荐流、详情页共用一份卡片投影）：soldCount ≤0 不显示（"已售 0"是负资产）；<1 万显示「已售 N」；≥1 万折成「已售 1.2万」（保留一位小数、整数万去尾写「1万」）。
- **[PRD-69]** 详情页规格选择：规格维度名→值的选中集是唯一真源并同步进 URL（skuId 由选择推导，不另存）；URL 里的脏规格（维度/值已不存在）收窄为有效集，不可解析退化为"未选规格"而非报错；同值再点一次 = 取消该维度。售罄置灰判定：某值在"当前其他维度已选"约束下不存在 stock>0 的 SKU 即不可选。
- **[PRD-70]** 详情页价格/库存文案：选中全部规格 → 该 SKU 价 + 精确库存文案（0 显示"该规格售罄"）；未选全 → SPU 价格区间下限（上下限相同不显示区间）、任一 SKU 有货即"有货"否则"暂时缺货"；划线价仅选中 SKU 且有 originalPrice 时展示。
    - **划线价只画严格高于成交价的那条**：PRD-39 允许 `original_price == price`（相等是合法数据），但相等意味着一分钱没让，画出来就是「原价 ¥19 压着 ¥19」的假折扣。判据全站一处（`@shop/common` 的 `strikethroughPrice`），在各领域的 wire→领域投影里生效（详情页 `derivePriceView`、购物车 `deriveCartItemView`、订单 `toOrderItem`），渲染层只看「有没有这个字段」——同一个商品在详情页划线、到订单不划，用户会以为价格变了。
- **[PRD-71]** 买家可见库存即"可用量"（stock − frozen_stock），非总库存：详情页 SKU 数、加减购/结算的缺货判定同一口径。契约字段名仍叫 `stock`（`SkuResponse.from` 取的是 `StockView.availableStock()`），别被名字骗去当总量用；上架门槛那侧才用总量（PRD-42）。
- **[PRD-72]** 详情页单条购买数量上限 99 是**前端步进器上界**（展示约定，防一格灌进离谱数字）；服务端硬闸门是 1..999（`@Max(999)` + DB CHECK，见 ORD-03），两个数不是同一个约束、不要对齐成一个。选全规格后收紧为 min(数量, 该 SKU 可用库存)，步进器与提交值同受约束，不把超卖数量带进购物车。

## 九、卖家编辑限制（前端规则表，后端兜底镜像）

- **[PRD-74]** 卖家端「状态 × 能力」表（后端状态机的声明式镜像，真值裁决在后端 409）：DRAFT——可切类目、可改规格、可发布（立即上架/放仓库）、价格可留空；WAREHOUSE——类目锁定、可改规格、价格必填、保存不回退状态、上架动作回列表；PUBLISHED——标题/图片/价格/库存随时改实时生效，改规格或类目必须先下架。
- **[PRD-75]** 卖家发布预检：将发布（提交/入库）时存在未设价 SKU 即拦（"还有 SKU 未设置价格，请补全后再发布"）；非草稿会话保存时价格必填同样拦。后端 ensurePublishable/price 必填兜底。
- **[PRD-76]** 卖家保存 SKU 只回传"已设价且已建档"的行（未设价不发——草稿无门槛，不把空价写成 0）；库存未填按 0 落库；编码空串省略。
- **[PRD-77]** 价格输入规则：非负「元」、最多两位小数，换算成分 + 平台币种；库存/数量输入为非负整数；0 元是合法价（null 才表示未设置）。
- **[PRD-78]** 发布流程：新建必须先选到末级（叶子）类目才能继续（三级列选择器，最多三级与后端 MAX_LEVEL 对齐）；SKU 组合在前端按模板选值本地算笛卡尔积预览（无选值 = 单规格 1 行），保存时才调后端建档。
- **[PRD-79]** 卖家工作台列表排序白名单：createdAt 升/降（默认降）、stock 升/降（跨模块聚合，全量取回内存排序再手动分页）、soldCount 升/降；库存排序对整店商品生效，代价是每请求遍历全店商品（单店规模可接受的既定取舍）。
- **[PRD-80]** 卖家详情编辑只回显"当前规格快照能产出的组合"的 SKU 行——对账停用的历史残留不打扰卖家（行仍在库，重新选回组合时价格库存原样带回）。

## 错误码 → 前端行为

- **[PRD-81]** `INSUFFICIENT_STOCK`（409）：前端引导改数量/移除后重新结算；detail「商品库存不足，请调整数量」不点名 SKU——多 SKU 单不知是哪件不足。
