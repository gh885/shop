# 卖家子账号体系改造计划

> 按「淘宝式」对齐卖家子账号体系（2026-10-13 拍板）：独立子账号凭证 + 建号/手机验证激活 + 独立登录 + 停用/密码重置 + 操作日志，另有两个带触发器的后置阶段。
>
> 本文是**路线图**，不是规范：每阶段开工前立 ADR / 改业务规则条目，落地后同步
> [authorization-matrix.md](conventions/authorization-matrix.md)（§三 卖家表、§七 `/shops` 登记、§八 留白）。
> 阶段顺序与触发条件以本文为准；实现细节在各阶段自己的 ADR 与改动里。

## 现状与目标

|          | 现状（一期）                                            | 目标（淘宝式）                                          |
| -------- | ------------------------------------------------------- | ------------------------------------------------------- |
| 凭证     | 一套账号（手机号 = 身份），子账号 = 普通账号 + 成员关系 | 独立子账号凭证（登录名 + 密码），工作身份与私人身份分离 |
| 建号     | 店主邀请 → 对方确认                                     | 店主创建 → 员工手机验证激活                             |
| 登录     | 普通登录 + `X-Shop-Id` 选店                             | 独立登录入口（子账号凭证登录工作台）                    |
| 停用     | 只有移除（删关系）                                      | 停用/启用中间态 + 店主重置密码                          |
| 留痕     | 订单有库内流水但无出口；其余动作无流水                  | 店主可查的子账号操作日志                                |
| 数据范围 | 成员看全店                                              | （触发器）「全部 / 仅分配给我」档位                     |
| 角色     | 5 个功能码直接勾                                        | （触发器）角色/岗位模板                                 |

已对齐、不动：授权开关模型、全量替换、收权下一请求生效、越权隔离（双锁）、离职回收。

## 阶段一：独立凭证（地基，单独立项）

**验收口径**：店主创建子账号（设登录名 + 密码）→ 员工首次登录激活（短信验证本人手机号）→ 用子账号凭证登录卖家工作台 → 子账号不能登录买家端（纯工作身份）→ 店主可停用/启用、重置密码。

**激活口径**：短信验证本人手机号，复用现有短信通道（含限流）；**身份证不入库**——平台的身份锚点本来就是手机号（与买家账号同一套信任模型），没有实名设施也不自建（存身份证号 = 敏感个人信息，合规成本远大于收益）；同店一个手机号只能激活一个子账号。激活时记录「已验证手机号 + 激活时间」作为追责锚点；实名认证留到「追责到自然人」成为硬需求时再立（届时接三方认证，不自存号）。

**改造面清单**：

- **auth 域**：新凭证类型（现为 `kind=user|staff` 两种）与登录接口；子账号不走短信自助找回，走店主重置；
- **过滤器链**：`ShopMembershipFilter` 职责变化——从「用户 + 成员关系」装载店铺上下文，变为「子账号凭证自带店铺」；
- **权限解析**：`SellerPermissionResolver` 改从子账号读码；**判权每请求实时求值的口径保持不变**（收权/停用下一请求生效）；
- **店铺模块**：邀请端点（`/shops/invites/**`）退场，成员表按凭证模型改造；
- **前端**：卖家端登录页（子账号入口）+ 子账号管理页（创建/停用/重置密码/勾权限）；
- **门禁联动**：`PermissionVocabularyTest`（`/shops` 真实路由清单）、`ShopEndpointGuardTest`（§七 登记表）、`SellerMemberPermissionIT`（收权即时生效用例迁到新模型）、`authorization-matrix.md` 三处同步。

**前置动作**：立 ADR——「子账号凭证模型：统一账号 + 成员关系 vs 独立子账号凭证」，记录取舍、代价、何时重新评估。

**明确不做**：双轨与迁移脚本——按项目规则（无需向后兼容、无需数据迁移），一期成员关系直接替换。

**登录名形状**待 ADR 定（淘宝是 `店铺名:子账号名`）。

## 阶段二：操作日志（店主可查「谁干了啥」）

- **记什么**：卖家工作台全部写操作——商品改价/上下架/规格、发货、售后裁决、券操作、地址与运费模板、成员与权限变更（含权限调整前后值）；
- **放哪**：新表（店铺维度、append-only）+ 查询端点；**不进治理账本**（`audit.audit_records` 的边界见 GEN-65/69：账本只记平台治理动作）；
- **与既有流水的关系**：`orders.order_status_log` 已有逐笔（前态/后态/动作/发起方），加一个查询出口即可；售后协商的 `ticket_events` 不动；
- **可见性**：店主可见全部；成员是否可见「自己的操作」随实现定；
- **前端**：卖家端「操作日志」页。

## 阶段三：停用中间态

- 子账号状态加 `DISABLED` 档：停用 = 保留凭证、立即失效（判权 fail-close 保持）、可解冻；与「移除」（删关系/删凭证）区分；
- 若阶段一已落地，停用挂在子账号凭证上，本阶段主要是状态机 + 前端入口；
- 大小：小。

## 阶段四：数据范围档位（触发器：跟单业务出现）

- **前置业务**：「订单分配给谁」——先立客服跟单需求（分配/接待/绩效），权限档位跟着它走；没有分配，「仅自己的单」不存在，单独做权限开关是空开关；
- **做成什么样**：订单模块增加「全部 / 仅分配给我」档位；mapper 过滤从「店铺」扩展到「店铺 × 分配」；
- **触发器**：第一个多客服店铺出现，或跟单需求进入 TODO。

## 阶段五：角色模板（触发器：权限码拆细）

- 角色 = 功能码（× 数据范围）的打包，预设岗位（客服/运营/仓储/财务）+ 自定义；
- **触发器**：权限码从 5 个合并码拆细之后才有意义（拆码触发器见 [permission-codes.md](conventions/permission-codes.md)：第一个「能看不能改」岗位出现）。

## 不做

- **部门树**：不做（几十人店铺才有意义）；
- **多店/主体层**：另行讨论，触发器 = 第一个多店商户（见 [authorization-matrix.md](conventions/authorization-matrix.md) §八 同族留白）。

## 阶段总表

| 阶段          | 状态   | 触发器                   | 大小              | 主要动到的面                           |
| ------------- | ------ | ------------------------ | ----------------- | -------------------------------------- |
| 一 独立凭证   | 待开工 | 拍板即做（需先立 ADR）   | 大（auth 全链路） | auth / 过滤器 / 权限解析 / shop / 前端 |
| 二 操作日志   | 排队   | 阶段一之后               | 中                | 新表 + 卖家端页                        |
| 三 停用中间态 | 排队   | 阶段一之后（或随一落地） | 小                | 状态机 + 前端                          |
| 四 数据范围   | 待触发 | 跟单业务出现             | 大                | order 分配 + mapper 收口               |
| 五 角色模板   | 待触发 | 权限码拆细后             | 中                | 码打包 + 前端                          |
