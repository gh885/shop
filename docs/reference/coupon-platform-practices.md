# 优惠券平台做法对照（淘系 / 京东 / 抖店）

> 目的：优惠券的"有哪几种"在公开资料里被讲成一堆券种清单（店铺券、品类券、京券、东券、裂变券…），
> 照着清单做设计会产出一堆同义枚举。这份把**平台实际规则**摊开，拆成正交维度，供 `docs/decisions/coupon.md`
> 的规则模型与分期对照。
>
> **快照日期：2026-09**。可信度分层（重要，别把二手当一手用）：
>
> - **一手**：京东官方帮助中心两页（券种定义、叠加顺序、退回矩阵都有原文与算例）。
> - **二手**：淘系的天猫营销工具说明与"优惠券叠加规则"来自服务商/攻略站与商家后台口径，
>   方向可信（与 2020 双 11「平行式优惠」改革一致），**具体数字与例外以商家后台现行规则为准**。
> - **仅记录概念**：抖店的"承担属性"只拿到规则标题与产品文档索引，正文未取到。
> - **未调研**：拼多多、美团。

## 1. 一句话结论

**"券种"是 6 个正交维度的组合命名，不是一个枚举列表。** 平台自己也是这么拆的——
京东官方原话：「从**使用限额**分为京券和东券；从**商品品类**进一步划分，分为限品类京券和东券；
从**销售主体**进一步划分，分为限店铺京券和东券；从**优惠券存在形式**划分，分为实体密码券和账户电子券两种。」

所以设计时该问的不是"支持几种券"，而是"**每个维度我支持到第几个取值**"。

## 2. 六个正交维度

| 维度           | 取值                                                                                     | 平台实例                                                                                          |
| -------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **优惠形式**   | 满减（满 X 减 Y）· 折扣（N 折，通常带封顶）· 无门槛直减 · 运费/包邮 · 赠品 · 换购 · 免息 | 京东运费券；白条/花呗分期免息；淘系单品宝（折扣/促销价）                                          |
| **适用范围**   | 店铺 · 商品（SPU/SKU）· 品类（含子类目）· 跨店（多店累计）· 区域 · 渠道                  | 京东店铺券/限品类券/区域专享券/平台专享券；淘系店铺券/商品券/品类券/跨店满减                      |
| **门槛口径**   | 有门槛 / 无门槛；**平行**（门槛按促销前金额判，各层独立）· 递进（按上层扣减后金额判）    | 京东"按总价促销前金额计算是否满足限额"；淘系 2020 双 11 起的「平行式优惠体系」                    |
| **领取/发放**  | 公开领取 · 定向发放 · 口令 · 裂变（分享拉人）· 入会/关注 · 积分兑换 · 下单返 · 加购召回  | 淘系"全网自动推广/官方渠道推广/自有渠道推广"、裂变券、购物车惊喜券；京东买赠、京豆兑换、PLUS 权益 |
| **承担方**     | 商家 · 平台 · 各半 · 第三方（政府消费券/国补）                                           | 淘系跨店级含"消费券"；抖店称"优惠券承担属性"                                                      |
| **载体与时效** | 电子券 / 密码券（兑换码）；绝对时间窗 / 领取后 N 天；有价券（花钱买券包）                | 京东"实体密码券和账户电子券"；淘系有价券                                                          |

被讲得最像"两种券"的那组，其实只是**一个轴的两端**：

|            | 京券                                      | 东券                         |
| ---------- | ----------------------------------------- | ---------------------------- |
| 使用限额   | 无门槛，按面值抵                          | 有门槛（满 X 减 Y）          |
| 叠加       | 多张可叠（同店/同品类内部有约束）         | 同类型在同一商品上只能用一张 |
| 找零       | **不找零**（100 元券付 89 元，11 元不退） | —                            |
| 是否可共存 | 京券与东券**互斥**，不能同单使用          | 同左                         |

## 3. 淘系：四层优惠层级与"平行式优惠"

**四层（从下到上）**：

1. **单品级**——单品宝（商品/SKU 级打折、减现、促销价）
2. **店铺级**——店铺宝（满元减/赠、满件折/赠）+ **优惠券**（店铺券、商品券、有价券、裂变券、阿里妈妈券）
3. **跨店级**——跨店满减、品类券、消费券
4. **资产级**——红包、淘金币、积分

对券最关键的两条结论：

- **券属于店铺级**。所以：可与跨店级、单品级、红包/淘金币叠加；**不可与店铺级其它券叠加**（店铺券与商品券不能同时生效）。
- **平行式优惠（2020 双 11 起）**：各层门槛**各自按促销前金额独立判定**，而不是拿上一层扣减后的金额去判。平行式带来的连锁规则：
  会员折扣/积分抵扣的计算位置会影响券门槛；**预售定金膨胀部分不计入后续满减门槛**；**运费不计入满减门槛**；SKU 级活动互斥组会让整单优惠失效。

**核销规则（2023 改版，与"一单一券"时代不同）**：

- 门槛按**子订单**算（同商品 + 同 SKU + 同收货地址聚合），一笔订单可以核销多张券。
- **一件商品/SKU 至多核销 1 张券**；多张券圈选同一商品时**取最优生效，不叠加**。
- 店铺券与商品券**圈品重叠 → 取最优**；圈品不重叠 → 可分别生效。
- 商家未设限领时，单店消费者可领券张数上限 15 张。

## 4. 京东：顺序扣减 + 平行门槛

京东的叠加与淘系最大的差别**不在能不能叠，而在门槛怎么算和扣减有没有先后**。官方原文与算例：

> 按照**店铺东券、全品类东券使用顺序，依次扣减东券金额**。根据订单中所购可用券商品的总金额**或参加总价促销前的金额**（指单品促销、返现后的金额…）计算是否满足东券使用限额。

即：**扣减有先后顺序，门槛一律按促销前金额判**。这个"或"字是平行门槛的表述，抄漏了会得出"券越叠越不能用"的错误实现。

叠加的硬约束（官方算例归纳）：

- 全品类东券**每单最多一张**；同类型东券在**同一商品上只能用一张**。
- 限品类券之间可叠的前提是**适用商品范围"完全一致"或"完全不一致"**；**部分重叠则不可叠加**（官方原例：券 1 适用 A+B、券 2 适用 B+C → 不可叠）。
- 京券与东券**互斥**；两者都可与运费券、E 卡、京豆同单使用。
- 运费券**只抵运费**，可多张叠加、不找零，虚拟商品与秒杀/夺宝岛等特殊流程不可用。
- 平台专享券（客户端/微信/手 Q）受渠道限制，平台专享京券在这些渠道**每单仅一张**；区域专享券按配送地址判定可用。
- 预售尾款**仅支持东券**（全品类/限品类/店铺东券）。
- **优惠部分不开具发票。**

## 5. 退回矩阵（京东官方，客诉最集中的地方）

京东把**取消**与**售后退货**分开，再按券种细分。核心口径：

| 场景           | 京券                               | 东券                                                  |
| -------------- | ---------------------------------- | ----------------------------------------------------- |
| 未拆单取消     | 返还原券                           | 返还原券                                              |
| 拆单后取消     | 部分不返还；全品类京券可能折成京豆 | 返还（旧的"12 月 4 日前"版本）／现行版本口径更严      |
| **整单退货**   | 按商品售价**比例拆分**折成京豆返还 | 全品类东券：所有商品退完才返还；限品类/店铺券：不返还 |
| **部分退货**   | 化整为零，以京豆形式等同返还       | 不返还                                                |
| 限店铺京券退货 | 不返还                             | —                                                     |
| 运费券退货     | 不返还                             | —                                                     |

两条容易忽略但很关键的：

- "**按商品售价所占订单金额比例拆分各支付金额**"——这就是**优惠分摊**。没有分摊模型，就没有"部分退款"能力，只能整单退。
- 退回时券**可能已过期**，京东的处理是"咨询客服发放新券"（现行帮助页第 8 条）——与本仓库一期"退款补发新券"的取舍同向。

## 6. 发放与领取渠道（券的"发行侧"）

**先纠正一个常见误解**："领取方式"与"券种"不是一一对应的。区分领取方式的轴是**发放来源**，同一个券种可以走多种发放方式；
而且**平台上的多数优惠用户根本不需要"领"**。真正的机制只有三种：

| 机制                         | 用户的动作                                           | 典型实例                                                                 |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| **主动领取**（入券包）       | 点"领取"；裂变要先分享、口令要先输码、有价券要先付钱 | 店铺券、商品券、品类券、会场券、口令券、裂变券、有价券                   |
| **自动生效**（不领）         | 无动作，满足条件即扣                                 | **跨店满减**、官方立减/单品直降、国家消费补贴                            |
| **系统定向发放**（自动入包） | 无动作，券自己出现在券包里                           | 入会券、关注店铺券、新人券、复购券、88VIP 权益券、购物车惊喜券、直播间券 |

另有若干**入口位置**（不是机制差异）：店铺首页、商品详情页、活动会场、客服/群/短信、直播、积分兑换、买赠。
淘系把它归纳成"全网自动推广 / 官方渠道推广 / 自有渠道推广"三种推广方式。

**"自动生效"那一档最关键**：跨店满减无需手动领取，系统识别带标识的商品自动计算——
计算基数是**活动价**（已扣单品直降/官方立减），**运费、税金、运费险、增值服务不计入门槛**，
优惠额再按各商品价格**比例分摊**到每一件上。所以"不用领的券"反而更需要一套清晰的门槛口径与分摊规则。

渠道清单（券当投放工具用，不只是"挂在店铺首页让人领"）：

| 渠道                                       | 说明                                                                             |
| ------------------------------------------ | -------------------------------------------------------------------------------- |
| 全网自动推广 / 官方渠道推广 / 自有渠道推广 | 淘系优惠券的三种推广方式：公域自动分发、官方活动位、商家自有渠道（客服/群/短信） |
| 裂变券                                     | 分享给好友拉人，分享者与被分享者都得益                                           |
| 购物车惊喜券                               | 对"已加购未下单"的用户在购物车页定向推送，临门一脚                               |
| 入会券 / 关注店铺券 / 群享券               | 会员与粉丝运营入口，本质是"定向发放"的自动化形态                                 |
| 直播间券                                   | 场景化定向发放                                                                   |
| 京豆/积分兑换、PLUS 权益、买赠             | 京东侧的资产兑换与权益发放                                                       |

> 一期只有"公开领取"这一种，`user_coupons.source` 已经是为发放渠道预留的扩展位。

### 6.1 用户为什么会晕：三个维度要自己在脑子里交叉判定

用户视角的复杂度不是"券种多"，而是**每张券都要同时判三件互不相干的事**：

1. **适用范围**（能买什么）：全平台 / 店铺 / 品类 / 指定商品 —— 文案常写"指定商品"，用户只能一件件去对；
2. **门槛**（买多少）：满 X 减 Y / 无门槛，且基数含不含运费、含不含已降价的差额，各平台口径还不同；
3. **叠加**（能不能一起用）：层内互斥、层间可叠、扣减还有固定顺序。

平台的补救措施：领券处就写明范围（"仅限美妆品类可用"）、结算页只列可用券并默认选最优、
给出"预估到手价"与优惠明细、对不可用的券给出原因。

但最能说明问题的是：**淘系把扣减顺序讲成了给用户背的口诀**（单品直降 → 店铺券 → 品类券 → 跨店满减 → 88VIP 95 折 → 超级红包 → 国家补贴）。
一个连顺序都要用户自己记的系统，就是设计失败的证据——**当规则需要用户理解时才生效，复杂度已经从系统漏到用户身上了**。
设计目标应该是让规则在**结构上**不产生歧义（一店一张券就没有"先用哪张"的问题），而不是靠页面文案去解释。

### 6.2 "选择方式"与"发放控制"是两个正交问题

常见误解是把它们对起来讲（"指定领取 vs 随机领取"）。实际上要分两个问题问：

| 问题               | 取值                                                                                                                       | 用户感受                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| **谁决定你领哪张** | ① **用户选**（指定领取：领券区列出 N 张，点哪张领哪张）② **系统给**（券包/礼包一次领多张、定向发放、互动玩法抽奖）         | 选：有掌控感但要点；给：省事但常领到用不上的券 |
| **你能不能领到**   | ① 人人有份（不限量）② **先到先得**（限量，领完即止，即"抢券"）③ 定时开放（指定时刻起可领）④ 资格限定（会员/新客/定向人群） | 先到先得 = 有紧迫感，也最容易落空              |

**所以"抢券"不是"指定领取"的对立面**，它是**发放控制**：一张指定券完全可以同时是限量的（要点、要抢、可能抢不到）。
"随机"则属于**选择方式**里的"系统给"，而且多数情况下随机的不是商品券本身，而是**红包/互动玩法奖励**——
标准商品券（店铺券/商品券/品类券）在店铺页与商品页都是**列出让你挑**的；券包/礼包是"打包给你"，但一般也明示含哪几张。
真正"不告诉你领到什么"的盲盒型券只出现在少量玩法场景里。

**对本仓库的意义**：一期是"用户选 + 先到先得"，即左下角那个格子——已经是**指定领取 + 抢券**，
`issued_quantity >= total_quantity → soldOut` 就是先到先得闸门。

把它讲给用户还需要什么（前端实现时核实过，比预想的多一格）：

| 想说的话      | 一期够不够                                                                      | 说明                                                                                           |
| ------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 「已领完」    | ✅ 够（`soldOut`）                                                              | 领完的券仍出现在列表里并置灰，不是消失                                                         |
| 「x 点开抢」  | ✅ 够（`validFrom` 即可领时段起点）                                             | 但可领列表本身只列已开始的券，所以买家侧看不到"未开始"这一态                                   |
| 「仅剩 N 张」 | ❌ **不够**（`ClaimableCouponResponse` 只有 `soldOut` 布尔，没有 total/issued） | 要做就得给匿名端点加 `remainingQuantity`；本期没做，也不该为一句紧迫感文案给匿名接口加库存口径 |

## 8. 对本仓库的映射

一期实现的口径详见 `docs/decisions/coupon.md`。对照上面的维度表：

**已覆盖的轴**：满减 × 店铺级 × 有门槛/无门槛 × 公开领取 × 商家承担 × 绝对时间窗 × 电子券。

**与平台一致、属于"抄对了"的部分**：

| 本仓库做法                                                   | 平台对应规则                                     |
| ------------------------------------------------------------ | ------------------------------------------------ |
| `threshold` 按同店商品小计判定，不含运费，券后不再重复计门槛 | 淘系平行式优惠；京东"按总价促销前金额计算"       |
| 每店最多一张券 + 金额降序默认选                              | "一件商品至多核销一张券""圈品重叠取最优，不叠加" |
| 券面额大于基数时封顶，不找零、不跨店抵扣                     | 京东"差额部分不抵扣其他商品，且不予退回"         |
| 不可用一律给原因码而不是 boolean                             | 平台均按券种差异给出不可用提示                   |
| 承担方落快照（`CouponBearer`）                               | 抖店"优惠券承担属性"、京东平台/区域专享券        |
| 退款补发新券，不退回原券                                     | 京东"返回的优惠券已过期可发放新券"               |

**缺口分级**（"变体"= 不动结构，只加分支；"机制"= 需要新模型）：

| 缺口                      | 类型 | 关键成本                                                                   |
| ------------------------- | ---- | -------------------------------------------------------------------------- |
| 折扣券（N 折 + 封顶）     | 变体 | 评估器加分支                                                               |
| 相对有效期（领取后 N 天） | 变体 | 模板存天数，领取时换算成绝对时间（一期已把"领取即固化绝对时间"的机制建好） |
| 定向发放 / 平台发券       | 入口 | 缺"后台给指定用户发券"的入口                                               |
| 运费券                    | 机制 | 要抵运费，与商品券口径不同且可叠加                                         |
| 品类券 / 商品券           | 机制 | 引入"券的适用商品集合"，是结构改动最大的一次                               |
| 跨店满减 + 优惠分摊       | 机制 | 分摊模型 + 承担方分账 + 部分退款；会反向改订单金额口径                     |
