# 商品搜索方案决策

- **状态**：一期已落 PostgreSQL `pg_trgm`，外部搜索服务暂不引入
- **决策日期**：2026-09-25

## 背景

商品列表当前使用 `name LIKE '%keyword%'`，数据量上升后无法使用普通 B-tree 索引。搜索需要保留大小写不敏感的包含匹配，并覆盖商品名称和副标题。

## 方案比较

| 方案                        | 优点                                             | 代价                                            | 结论                     |
| --------------------------- | ------------------------------------------------ | ----------------------------------------------- | ------------------------ |
| PostgreSQL `pg_trgm` + GIN  | 复用现有数据库；支持 `%keyword%`；部署和回滚简单 | 索引占用空间；中文相关性仍需后续优化            | 一期采用                 |
| PostgreSQL `tsvector` + GIN | 中文分词和排序能力强                             | 需要词典/分词配置；短语和部分子串召回需额外处理 | 后续需要相关性排序时评估 |
| 外部搜索服务                | 相关性、扩容和运营能力更强                       | 新基础设施、数据一致性、降级和成本              | 当前规模不采用           |

## 一期实现

- Flyway `V67` 启用 `pg_trgm`，分别给 `name`、`subtitle` 建 GIN trigram 索引。
- `ProductMapper.selectPublicPage` 用绑定参数执行 `ILIKE '%keyword%'`，名称或副标题任一命中即可；service 只把关键词递进去，不自己拼条件。
- 空关键词仍不添加搜索条件，保留原列表排序和分页语义。
- 重建索引：在维护窗口执行 `REINDEX INDEX CONCURRENTLY product.idx_products_name_trgm` 和 `product.idx_products_subtitle_trgm`；PostgreSQL 会在重建期间继续读写。

## 观测与后续

当前请求日志已记录路由和 latency；搜索零结果率与关键词耗时应在接入真实流量后按日聚合。出现以下信号时重新评估：

- 搜索 p95 超过 300ms；
- trigram 索引膨胀到数据库容量的 20% 以上；
- 需要相关度、同义词、拼写纠错或中文分词；
- 外部搜索服务能提供可量化的转化/召回收益。

切换外部服务时保留当前 `ILIKE` 路径作为开关和降级路径，避免搜索依赖变成交易链路单点。
