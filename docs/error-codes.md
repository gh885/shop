# Error Codes

只有前端**无法仅通过 HTTP status 区分**时才定义 code，否则省略 code，让 `detail` 承载用户提示。

| Code                              | HTTP | 前端行为                                                                                                                                                               | 后端触发场景                                                                                                             |
| --------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `SMS_RATE_LIMIT`                  | 429  | 提示失败文案，并同样起 60s 重发倒计时（共享 LoginForm：发码成功、或失败命中此码，都进倒计时）                                                                          | 同一 IP 或手机号频繁请求验证码                                                                                           |
| `SMS_DAILY_LIMIT`                 | 429  | 提示"今日验证码获取次数已达上限"                                                                                                                                       | 同一手机号当日发送量超过日限（20 条）                                                                                    |
| `SMS_CODE_EXPIRED`                | 400  | 提示"已过期"，由用户手动重新发码；无自动重取流程                                                                                                                       | 登录或重置密码验证码超时（5 分钟），或输错满 5 次被当场作废（第 5 次错仍报 `SMS_CODE_INVALID`，见下「实现事实补记」）    |
| `SMS_CODE_INVALID`                | 400  | 输入框标红，提示"验证码错误"                                                                                                                                           | 登录或重置密码验证码比对不通过                                                                                           |
| `CAPTCHA_REQUIRED`                | 400  | 提示"请先完成图形验证码"，刷新验证码图                                                                                                                                 | 发码请求未携带 captchaId / captchaCode                                                                                   |
| `CAPTCHA_EXPIRED`                 | 400  | 提示"验证码已过期"，自动刷新验证码图并让用户重输                                                                                                                       | 图形验证码超时（5 分钟）或已被消费                                                                                       |
| `CAPTCHA_INVALID`                 | 400  | 输入框标红，提示"图形验证码错误"，刷新验证码图                                                                                                                         | 图形验证码比对不通过（输错或大小写不符）                                                                                 |
| `TOKEN_EXPIRED`                   | 401  | 静默调用 refresh 续期；失败则降级为未登录                                                                                                                              | JWT access token 超过有效期（买家 10 分钟 / 员工 8 小时，见下方「实现事实补记」）                                        |
| `INVALID_TOKEN`                   | 401  | 清除用户状态，跳转登录页                                                                                                                                               | 未携带 token / 格式无效 / 类型错误 / 签名校验失败                                                                        |
| `REFRESH_TOKEN_REUSED`            | 410  | refresh 拦截器命中此码时 `tokenStore.clear()` 清登录态，410 原样冒泡由全局错误通道 toast 展示 detail（「所有设备已下线」）                                             | Refresh token 已被消费过（重放检测）                                                                                     |
| `USER_DISABLED`                   | 403  | 如实展示 detail"账号已被禁用"，无客服引导；下单被拦时无额外动作                                                                                                        | 用户状态非 ACTIVE（登录/刷新，及下单闸门 OrderService.create 经 account::api 查状态）                                    |
| `STAFF_DISABLED`                  | 403  | 提示"账号已被禁用"，引导联系平台管理员                                                                                                                                 | 平台员工登录时状态非 ACTIVE（StaffService.login）                                                                        |
| `PERMISSION_DENIED`               | 403  | 渲染"无权限"页/提示；区别于其他 403（非店铺成员等），不引导登录                                                                                                        | 已认证主体缺少接口所需权限码（PermissionInterceptor 判权失败）                                                           |
| `SHOP_NAME_TAKEN`                 | 400  | 开店表单店名字段标红 + toast 显示 detail（"店名已被使用，请换一个"），引导改名后重新提交                                                                               | 开店时店名已被全平台任一店铺占用（ShopService.createShop 预检；并发撞 uk_shops_name 唯一索引兜成同一 400，不看店铺状态） |
| `SHOP_LIMIT_EXCEEDED`             | 400  | toast 显示 detail（"每人最多开 1 家店铺"），开店入口可据此置灰；不引导重试                                                                                             | 当前用户在 shop.shop_members 已持有 ≥1 条 OWNER 成员记录（一人一店；被拒/被封店铺仍计数，子账号同闸）                    |
| `INSUFFICIENT_STOCK`              | 409  | 不点名具体 SKU：toast 展示后端 detail，用户自行改数量/移除商品后重新结算                                                                                               | 下单时条件扣减库存影响行数为 0（预览后商品被抢空）                                                                       |
| `COUPON_ALREADY_CLAIMED`          | 409  | 按钮置为"已领取"并提示，不引导重试                                                                                                                                     | 同一用户重复领取同一张券（每人每模板限领 1 张，唯一索引兜底）                                                            |
| `AFTER_SALE_ALREADY_REFUNDED`     | 409  | 提示"该订单已完成退款，不能再次申请售后"，不引导重试（终态，非可恢复冲突）                                                                                             | 买家申请售后时，该订单最新一张售后单为 REFUNDED（AfterSaleService.apply，V1 整单售后禁止二次退款）                       |
| `CATEGORY_NOT_LEAF`               | 400  | toast 显示 detail（"商品只能挂载到叶子类目（三级）"）；发品/编辑页类选择器引导改选三级类目                                                                             | 创建商品或草稿改挂类目时，目标类目 level≠3（CategoryService.requireMountableCategory）                                   |
| `CATEGORY_DISABLED`               | 400  | toast 显示 detail；引导改选启用类目                                                                                                                                    | 创建/改挂商品到已禁用类目，或父链上任一祖先禁用（与公开树「父级不可见整支剪掉」同口径）                                  |
| `ADDRESS_LIMIT_EXCEEDED`          | 400  | toast 显示 detail（"最多保存 20 条收货地址"）                                                                                                                          | 买家新增收货地址时未删地址已达 20 条（AddressService.create；软删不占名额）                                              |
| `MERCHANT_ADDRESS_LIMIT_EXCEEDED` | 400  | toast 显示 detail（"最多添加 200 条地址"，对齐 seller 工作台文案）                                                                                                     | 商家新增地址时本店未删地址已达 200 条（MerchantAddressService.create）                                                   |
| `BANNER_TIME_RANGE_INVALID`       | 400  | 生效/失效时间两个输入框标红，提示"banner 失效时间必须晚于生效时间"，不整页 toast                                                                                       | ContentService.createBanner / updateBanner：起止都给（或 update 时与库中原窗口合并后两端齐全）且 endAt 不晚于 startAt    |
| `RESPONSE_VALIDATION_FAILED`      | 2xx  | 前端生成错误，非后端返回：dev 完整打印 issues 尽早暴露；生产上报监控，读路径按查询错误状态在**渲染层**降级（错误边界 / 空态），不在 queryFn 里伪造兜底数据；写路径强抛 | 后端契约漂移——响应 2xx 但 payload 不符合 OpenAPI 契约（前端 zod responseValidator 校验失败）                             |

## 实现事实补记

- **access token 有效期**：买家 10 分钟（`access-token-expiration: 600000`）、员工 8 小时（`staff-access-token-expiration: 28800000`），见 `apps/server/src/main/resources/application.yml:104-105`。
- **验证码输错计数**（`SmsCodeService`，上限 5 次）：第 5 次输错**当场焚码**（删 Redis 验证码），但**当次响应仍是 `SMS_CODE_INVALID`**；之后再输码才因「无哈希」报 `SMS_CODE_EXPIRED`。重新发码会清尝试计数、重新计数。
- **refresh 并发宽限期**（15s，`RefreshTokenStore`）：已消费的 refresh token 在宽限期内再被消费判为多标签页并发竞争，返回 **401 且无 code**，detail「登录状态正在其他页面刷新，请稍后重试」——前端当普通 401 走即可，勿按重放处理；超出宽限期才判为盗用：全端吊销 + 410 `REFRESH_TOKEN_REUSED`。

## 设计原则

- **code 不是 HTTP status 的复述**：`RESOURCE_NOT_FOUND` / `FORBIDDEN` 不加，404/403 本身已表达
- **code 不是 debug 信息**：`AUTH_PASSWORD_TOO_SHORT` / `VALIDATION_ERROR` 不加，被前端校验拦截或 `errors` 列表承载
- **code 不预设未来场景**：只在当前有明确区分需求时加
