# 订单生命周期：从创建到完成

> 端到端业务流程主线，跨 order / payment / logistics / aftersale / coupon / cart 模块。
> 视角：业务主线为主、技术触点为辅。接口只到「谁在什么时机调哪个接口、做什么、结果如何」，不展开参数与内部逻辑。
> 单条可被代码引用的业务规则在 [../business-rules/](../business-rules/)（order / payment / aftersale / logistics / coupon），本文只串流程不复述编号条款。

## 1. 一句话概述

买家从购物车/商品详情页发起结算，系统按店铺拆单并锁定库存，进入收银台完成支付（可跳转外部渠道），支付后卖家发货、买家确认收货（或超时自动完成），全链路通过状态机 + 定时扫描 + 领域事件驱动。

## 2. 订单状态机

| 实体                       | 状态     | 含义                                 | 允许迁移                                                                    |
| -------------------------- | -------- | ------------------------------------ | --------------------------------------------------------------------------- |
| 主订单 `PENDING_PAYMENT`   | 待支付   | 一次结算一张，承载支付与金额汇总     | → 已支付、→ 已关闭                                                          |
| 主订单 `PAID`              | 已支付   | 全部子订单付清                       | → 已关闭                                                                    |
| 主订单 `CLOSED`            | 已关闭   | 取消 / 超时 / 全额退款               | 终态                                                                        |
| 子订单 `PAID`              | 待发货   | 创建即此态，`paid_at` 为空表示未付款 | → 部分发货、→ 已发货、→ 已取消                                              |
| 子订单 `PARTIALLY_SHIPPED` | 部分发货 | 有行结清、仍有行未结清               | → 待发货（取消包裹回退）、→ 部分发货（追加）、→ 已发货                      |
| 子订单 `SHIPPED`           | 已发货   | 全部行结清，等签收                   | → 待发货 / 部分发货（取消包裹回退）、→ 已发货（追加）、→ 已完成（全部签收） |
| 子订单 `COMPLETED`         | 已完成   | 履约闭环                             | 终态                                                                        |
| 子订单 `CANCELLED`         | 已取消   | 关单 / 取消                          | 终态                                                                        |

> 子订单履约态**允许回退**：取消已发出的包裹会把有效发货量退回去，然后按结清量重算（docs/domain/order-model.md §8）。箭头表示可达关系，不表示单向。

操作方 `Actor`：买家 / 卖家 / 系统。每次迁移记录在订单状态审计日志（原状态、新状态、操作方、原因）。

售后状态是**正交轨道**——独立工单状态机（申请中 → 已退款 / 退回中 / 已拒绝 / 已撤销；退回中 → 已退款 / 已拒绝 / 已撤销），不与主状态机耦合；一笔已完成订单仍可能有售后活动。

## 3. 端到端流程总览

| 阶段           | 参与角色                   | 用户动作                                                               | 系统技术触点                                                                                                                                                         | 状态变化                       |
| -------------- | -------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| 结算预览       | 买家                       | 购物车点「去结算」，进入订单确认页                                     | 前端调用「订单预览接口」，返回价格、运费、可用券                                                                                                                     | —                              |
| 创建订单       | 买家 → 系统                | 订单确认页点「提交订单」                                               | 前端调用「创建订单接口」；校验库存/账号/店铺 → 落一张主订单 + 按店铺拆子订单 → 锁定库存 → 锁定优惠券 → 发布「订单已创建事件」（清购物车）                            | → 主订单待支付；子订单待发货   |
| 支付           | 买家 → 外部支付平台 → 系统 | 收银台点「确认支付」；外部页面完成付款；回跳页点「我已付款，查询结果」 | 「发起支付接口」取跳转链接 → 浏览器跳转外部收银台 → 外部平台同步回跳 → 「确认支付接口」→ 后端向外部平台查询验证 → 逐子订单扣减冻结库存/核销券 → 全部付清后推进主订单 | 主订单 待支付 → 已支付         |
| 发货           | 卖家                       | 卖家订单页点「发货」，选物流公司 + 填单号 + 勾本次发的行与件数         | 「录单接口」落待发货包裹与发货单行 → 「交寄接口」入账并重算履约态；承运商揽收推送会自动交寄                                                                          | 已支付 → 部分发货 / 待收货     |
| 确认收货       | 买家 / 系统                | 买家点「确认收货」；或物流签收 / 超时系统自动完成                      | 物流签收经 `order::api` 重算（全部结清 + 全部签收 = 完成）；「确认收货接口」与定时扫描是承运商不推签收时的兜底                                                       | 待收货 → 已完成                |
| 取消（未支付） | 买家 / 系统                | 买家点「取消订单」；或 15 分钟超时自动关单                             | 「取消订单接口」或定时扫描释放冻结库存、解锁券                                                                                                                       | 待支付 → 已取消                |
| 取消（已支付） | 买家                       | 待发货状态点「取消订单」                                               | 「取消订单接口」→ 退库存、还券 → 发布「订单已取消事件」→ 支付模块向外部平台发起退款                                                                                  | 已支付 → 已取消                |
| 售后（正交线） | 买家 → 卖家 → 系统         | 买家申请售后 → 卖家同意/拒绝 → 买家寄回 → 卖家确认收货退款             | 「申请售后」「同意/拒绝」「退货确认」等接口；通过时发布「售后退款事件」→ 支付模块退款                                                                                | 主状态不变；售后子状态独立流转 |

## 4. 主流程步骤表

| #   | 业务阶段       | 用户/角色动作                                                  | 技术触点                                                               | 系统处理结果                                                                                                         | 状态变化                                | 关键规则                                                                                                  |
| --- | -------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 1   | 结算预览       | 购物车勾选商品，点「去结算」                                   | 前端调用**订单预览接口**                                               | 返回按店铺分组的金额、运费、可用券                                                                                   | —                                       | 预览与下单走同一计价逻辑，保证「预览价 = 下单价」                                                         |
| 2   | 创建订单       | 确认页选地址/券，点「提交订单」                                | 前端调用**创建订单接口**（带幂等键 checkoutKey）                       | 校验账号有效 → 校验商品可售 → 校验店铺营业 → 按店铺拆单 → 冻结库存 → 锁定券 → 发布**订单已创建事件**（同步清购物车） | → 待支付                                | 幂等：同一 checkoutKey 重复提交返回首次结果；库存不足整批回滚；恶意买家限流（待付款≥10 或 24h 内取消≥10） |
| 3   | 发起支付       | 收银台点「确认支付」                                           | 前端调用**发起支付接口**；后端在外部平台创建交易，返回跳转链接         | 创建支付单（待确认），**不改变订单状态**                                                                             | 支付单 → 待确认                         | 单笔按订单发起；合并支付按 checkoutKey 发起（当前仅模拟渠道）                                             |
| 4   | 外部付款       | 在外部支付页完成付款                                           | 外部平台浏览器同步回跳至**支付回跳页**                                 | 回跳页仅取支付单号用于后续查询，**不信任回跳携带的金额/状态参数**                                                    | —                                       | 回跳参数未签名，不可作为支付成功依据                                                                      |
| 5   | 确认支付       | 回跳页点「我已付款，查询结果」                                 | 前端调用**确认支付接口**；后端向外部平台**主动查询交易状态**           | 验证通过 → 支付单成功 → 同事务：扣减冻结库存、核销券、推进订单                                                       | 支付单 → 成功；订单 待支付 → **已支付** | 确认由用户点按钮触发，非挂载即发（防刷新重复查询）；以外部平台返回为准；幂等（已成功不重复处理）          |
| 6   | 卖家发货       | 订单管理页点「发货」，选物流公司 + 填单号 + 勾本次发的行与件数 | 前端调用**录单接口**（返回包裹主键）→ **交寄接口**                     | 落待发货包裹与发货单行；交寄后件数入账、重算履约态；承运商揽收推送自动交寄                                           | 已支付 → **部分发货 / 待收货**          | 一单一张待发货单；超发 409；交寄守卫按订单行结清量判定；运单号全局唯一                                    |
| 7   | 确认收货       | 订单详情点「确认收货」                                         | 前端调用**确认收货接口**                                               | 完成订单、累加商品销量                                                                                               | 待收货 → **已完成**                     | 物流签收会自动完成；该按钮只兜承运商不推签收的情况                                                        |
| 7b  | 超时自动完成   | （无）                                                         | 定时扫描任务（每 30 秒）扫描收货倒计时到期的待收货订单                 | 系统代为确认收货，但若存在进行中的售后工单则跳过该笔                                                                 | 待收货 → 已完成                         | 逐笔独立事务，单笔失败不冻整批；售后进行中不自动完成                                                      |
| 8   | 取消（未支付） | 点「取消订单」；或倒计时到期                                   | 手动 → **取消订单接口**；超时 → 定时扫描自动关单                       | 释放冻结库存、解锁优惠券                                                                                             | 待支付 → **已取消**                     | 倒计时 15 分钟；超时与手动走同一取消逻辑，仅操作方=系统                                                   |
| 9   | 取消（已支付） | 待发货状态点「取消订单」                                       | **取消订单接口** → 发布**订单已取消事件** → 支付模块向外部平台发起退款 | 退库存、还券（已核销的发新券补偿）、退款                                                                             | 已支付 → **已取消**                     | 退款失败不阻塞取消（买家权利优先），失败记录留人工对账                                                    |

## 5. 关键异常分支

| 异常场景                 | 触发条件                       | 技术触点                 | 业务处理                                           | 最终状态               |
| ------------------------ | ------------------------------ | ------------------------ | -------------------------------------------------- | ---------------------- |
| 支付超时关单             | 下单后 15 分钟内未完成确认支付 | 定时扫描任务             | 自动关闭订单、释放库存、解锁券                     | → 已取消               |
| 支付确认未生效           | 外部平台返回交易未成功         | 确认支付接口返回失败     | 前端展示「支付未生效」，允许重新发起或返回订单列表 | 仍待支付，等倒计时关单 |
| 退款失败（取消已支付单） | 外部平台退款异常               | 退款调用失败             | 取消不回滚；记录待人工对账                         | → 已取消（款项待对账） |
| 退款失败（售后退款）     | 外部平台退款异常               | 退款调用失败             | 严格模式：回滚售后状态，工单不生效                 | 售后回退到前态         |
| 库存不足                 | 创建订单时冻结库存失败         | 创建订单接口返回冲突     | 整批回滚，提示买家                                 | 无订单产生             |
| 店铺已关闭               | 创建订单时店铺非营业           | 创建订单接口返回冲突     | 拒绝下单                                           | 无订单产生             |
| 恶意买家限流             | 待付款≥10 或 24h 内取消≥10     | 创建订单接口返回频率限制 | 拒绝下单                                           | 无订单产生             |
| 售后进行中遇自动收货     | 收货倒计时到期但有进行中工单   | 定时扫描任务             | 跳过该笔，不自动完成                               | 保持待收货             |
| 重复提交订单             | 网络重试或用户双击             | 创建订单接口命中幂等键   | 返回首次创建结果，不重复创建                       | 正常                   |

## 6. 关键接口/回调清单

| 名称                     | 触发时机                  | 调用方 → 被调方                                | 业务用途                                     | 影响状态                     |
| ------------------------ | ------------------------- | ---------------------------------------------- | -------------------------------------------- | ---------------------------- |
| 订单预览接口             | 进入结算页、切换地址/券时 | 买家前端 → 订单服务                            | 返回按店铺分组的计价、运费、可用券           | 无（只读）                   |
| 创建订单接口             | 点「提交订单」            | 买家前端 → 订单服务                            | 校验+拆单+锁库存+锁券+发事件                 | → 待支付                     |
| 发起支付接口             | 点「确认支付」            | 买家前端 → 支付服务 → 外部支付平台             | 在外部平台创建交易，返回跳转链接             | 支付单 → 待确认              |
| 外部平台同步回跳         | 外部完成付款后浏览器跳转  | 外部支付平台 → 买家浏览器 → 前端回跳页         | 仅传递支付单号，不作付款依据                 | 无                           |
| 确认支付接口             | 点「我已付款，查询结果」  | 买家前端 → 支付服务 → 外部支付平台（主动查询） | 验证真实交易结果，推进订单                   | 支付单 → 成功；订单 → 已支付 |
| 取消订单接口             | 点「取消」                | 买家前端 → 订单服务                            | 按原状态释放库存/退券/触发退款               | → 已取消                     |
| 创建发货单接口           | 卖家点「发货」            | 卖家前端 → 物流服务                            | 记录包裹，启动收货倒计时                     | → 待收货                     |
| 确认收货接口             | 买家点「确认收货」        | 买家前端 → 订单服务                            | 完成订单、累加销量                           | → 已完成                     |
| 延长收货接口             | 买家点「延长收货」        | 买家前端 → 订单服务                            | 收货倒计时 +7 天（仅一次）                   | 状态不变，截止延后           |
| 定时扫描任务（支付超时） | 每 30 秒                  | 系统 → 订单服务                                | 关闭超时未支付订单                           | 待支付 → 已取消              |
| 定时扫描任务（收货超时） | 每 30 秒                  | 系统 → 订单服务                                | 自动完成超时未收货订单（售后中跳过）         | 待收货 → 已完成              |
| 订单已创建事件           | 订单持久化成功后          | 订单模块 → 购物车模块                          | 清除已购商品                                 | 无                           |
| 订单已取消事件           | 已支付订单取消成功后      | 订单模块 → 支付模块                            | 向外部平台发起退款                           | 支付单 → 已退款              |
| 售后退款事件             | 售后工单流转至「已退款」  | 售后模块 → 支付模块                            | 向外部平台发起退款（严格模式，失败回滚工单） | 支付单 → 已退款              |

## 7. 买家侧页面动线

```
商品详情页 ──加入购物车──→ 购物车页
                            │ 「去结算」
                            ▼
                         订单确认页 ──「提交订单」──→ 收银台
                                                       │ 「确认支付」
                          ┌── 模拟渠道：页内直接确认 ───┤
                          │                              └── 真实渠道：跳转外部收银台
                          ▼                                       │ 买家付款
                       支付成功                                   ▼
                          │                              支付回跳页
                          ▼                          「我已付款，查询结果」
                       我的订单列表                          ▼
                          │ 「详情」                  查询结果（成功 / 未生效）
                          ▼
                       订单详情页 ──「确认收货 / 取消 / 延长收货 / 申请售后 / 查看物流」
```

关键页面：购物车 → 订单确认 → 收银台（按主订单，一次结算只付一次）→ 支付回跳 → 我的订单列表（一张主订单一张卡，按主进度分页签）→ 订单详情（子订单粒度）→ 物流跟踪。

## 8. 待确认问题

1. **支付异步通知（notifyUrl）**：配置中有该字段，但确认支付走的是用户手动触发的同步查询。是否存在外部平台异步回调接口作兜底，还是仅预留？——待确认：外部平台异步通知接口
2. **真实渠道下的整单收款**：模型上一次结算只付一次（一张主订单），但真实渠道一笔交易对应一条子订单流水，收银台只能跳第一条；买家要串行点多次「去支付」才能付清，没有「一次付清」的引导（PAY-47）。上线真钱前要么做 N 次跳转的引导，要么立「一条渠道交易对应整张主订单」的模型。
3. **卖家不发货的平台介入**：付款后 3 天仅 UI 提醒、不自动推进；卖家持续不发货是否有平台介入或超时规则？
4. **部分退款**：当前取消是整单全额退，是否支持单笔订单内部分商品退款（非售后路径）？
5. **优惠券补偿规则**：已支付取消时「发新券补偿」，补偿券面额/有效期是否与原件一致，是否有次数限制？
