# i18n 约定

前端国际化的单一口径。所有判据的出处都在这：语言策略、生成门禁、评审层、编辑器接入。

## 语言策略（唯一真相源）

`contracts/i18n.config.yaml`——`zh-Hans-CN` 为源语言与默认语言，`en-US` 为目标语言，
`requireComplete: true`（每个 key 两种语言都必须有值），回退链 `zh-Hans-CN → [en-US]`，
平台时区钉死 `Asia/Shanghai`。前后端同源：前端经 `pnpm i18n:gen` 产出到
`packages/common/src/contract/locale-vocab.gen.ts`，后端 `SupportedLocales` 运行时读同一份 yaml。

## 词典布局

- **共享词典**：`packages/i18n/src/locales/{locale}/{namespace}.json`（confirm/copy/error/form/login/ui/validation…）。
  三端共用，作为所有 app 的 fallback namespace（`defaultNS: 'app'` + `fallbackNS: 'shared'`）。
  归属 `@shop/i18n`（运行时 `createI18n` 内建共享 fallback，各端只接自己的 resources）。
- **各端词典**：`apps/{web,seller,admin}/src/locales/{locale}/{namespace}.json`。
  app 专属内容留在 app——构建期 `import.meta.glob` 装配进各自 bundle。
- **key 是扁平点分串**（`"cart.toast.maxStock"`），namespace 前缀写进 key 本身，
  `keySeparator: false`——服务类型生成（key 字面量联合），不是嵌套对象。
- 插值用 ICU（`{count}`、`{count, plural, other {…}}`），运行时 i18next-icu。
- React 消费：`useT()` / `useT("namespace")`，类型由生成物约束（漏传参/错参数名编译报错）。

## 生成门禁（codegen，判「对不对」）

`scripts/contracts/i18n-codegen.mjs`（`pnpm i18n:gen` / `pnpm i18n:drift`），
失败不写任何生成物。判据：

1. 跨语言 key 完整覆盖（`requireComplete`）；
2. ICU 语法可编译（与运行时同一份 `intl-messageformat`），跨语言参数集合一致；
3. 消息内禁直接格式化金额（`MoneyInMessageError`）——金额只走 `formatMoney` / 共享 `Price`；
4. 译文不得与源语言逐字相同（豁免白名单 `IDENTICAL_TRANSLATION_OK` 在脚本顶部，加一条要写理由）；
5. 未使用 key 扫描（带引号整串匹配，宁可漏报不误伤）；
6. 生成物字节级漂移检查（`--check`，lefthook pre-push `i18n-drift` 与 CI 同一条命令）。

产物：各端 `messages.gen.ts`（key 联合、参数映射、翻译函数类型）+ `locale-vocab.gen.ts`。

## 评审层（x18n，判「好不好」）

`x18n.config.ts` 接入 [x18n](https://x18n.dev)（`@x18n/cli`，devDependencies），`pnpm i18n:check` 运行。
与 codegen 分工：**codegen 是生成门禁，x18n 是纯检查层，不接管运行时、不生成类型**。

- 配置要点：`keyStyle: 'flat'` + `keySeparator: false`（与运行时一致）；
  两条 resources pattern 对应共享词典与三端 catalog，namespace `app` + fallback `shared`；
  `usage.calls` 声明 `t` / `sharedMessage` / `message` / `err` 工厂与 `translate*` 出口，
  `usage.regex` 兜底非 `t()` 场景的字面 key（`labelKey` 等）。
- 与 codegen 重叠的检查（missing-key、placeholder、语法等）开 warning：双口径可对照，不重复拦。
- codegen 没有的增量：`stale-translation`（源文案改了译文没跟，按 git 历史）、
  `glossary`（术语表，词条在本 config）、`hard-string`（`extract.autoDetect`，info 级评审队列——
  vendored reui / ui 原语 / 域数据词表已在 `extract.ignoreByFile` 豁免）、
  `redundant-translation`、`identical-to-source`。
- `key-conflict` 关闭：三端 catalog 在单 config 下共享 `app` namespace，同名 key（如 `app.title`）
  是各端自己的消息不是冲突——真正的「谁在用」由 codegen 的未使用扫描守。
- 命令：`pnpm i18n:check`（人读）/ 加 `--json` 出稳定 JSON envelope（协议版本 + diagnostics +
  coverage，供 AI 审校）；`pnpm x18n ui` 起浏览器管理界面（本地模式可写文件，`x18n build`
  静态报表不写仓库）。
- lefthook pre-push `i18n-check` 作业与 `i18n-drift` 并列：error 才拦，warning 报出来给人看。
