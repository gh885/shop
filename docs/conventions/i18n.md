## 2. 当前 Locale 的解析与管理

买家端使用 `/{locale}/...` 语言路径，默认语言也带前缀；无语言前缀的页面入口解析语言后跳转到对应语言路径。卖家端和后台不使用语言路径，仅保存语言偏好。

- **解析顺序**：买家端 URL 显式语言 → 语言 cookie → 浏览器语言 → `defaultLocale`；卖家端和后台跳过 URL 层。SSR 从请求头 `Accept-Language` 读取浏览器语言，纯 SPA 读取 `navigator.languages`。规范化 BCP 47 标签后匹配支持清单；浏览器偏好按优先顺序处理，不跨繁简体猜测。无效 cookie 忽略，不支持的 URL 语言按无效路由处理。请求语言匹配不使用文案回退链。
- **偏好保存**：用户主动切换时写入 cookie，登录用户同时保存账号偏好；访问语言链接、浏览器自动匹配不保存偏好。登录时将账号偏好同步到 cookie；没有 URL 显式语言时，同时更新当前上下文。账号保存失败必须提示未同步，不能宣称保存成功。
- **切换**：目标语言及当前页面所需资源准备完成后再更新当前上下文、保存偏好；买家端同时更新语言 URL。加载失败保留原语言；连续切换以最后一次选择为准。同步更新文案、格式化和页面 `lang` / `dir`；文字方向从 Locale 的语言与文字系统推导。
- **SSR**：Locale 随请求解析，禁止进程级可变 Locale。客户端接管时沿用服务端传入的 Locale 和资源版本，不读取浏览器偏好重新选择。允许共享不可变资源，不允许共享用户语言状态。
- **传播**：翻译、格式化和需要本地化响应的 API 请求使用当前上下文；API 通过 `Accept-Language` 显式携带解析后的 Locale。语言相关数据的缓存键必须包含 Locale；无关数据不重复缓存。按 cookie 或请求头选语言的 SSR HTML 不进入公共共享缓存。

## 3. 翻译资源模型与交付

根配置是语言策略的唯一来源。`pnpm i18n:gen` 生成前端配置与消息类型，三端开发和构建前自动执行；后端启动读取同源的打包配置。生成物不手改。

UI 资源使用 UTF-8 JSON，消息语法使用 ICU MessageFormat。资源清单与类型从源资源生成，不手工维护平行清单。固定错误提示、校验提示、无障碍文案和页面标题属于 UI，不单独扩成内容类型。

### 3.1 组织与命名

- 文案放在所属应用或共享包内，按业务域和 Locale 分文件；文件不直接决定加载粒度。
- 使用完整的语义 key，例如 `checkout.placeOrder`；不使用原文，不强制固定层数。同一应用或共享包内，同一 Locale 的 key 不得重复。调用入口明确所属应用或共享包，不要求 key 携带应用前缀。
- 移动或拆分文件不改变 key。只有含义一致、需要一起修改的文案才共享；文字恰好相同不构成共享理由。

### 3.2 加载与回退

- `sourceLocale` 是该内容类型的键与参数基准，不等于站点默认语言。`requireComplete` 要求目标语言自身完整，不能把回退资源算入覆盖。未声明的 Locale 或内容类型不算支持；`fallback` 必须显式填写，空列表表示终止。
- 按当前页面依赖加载资源包，不一次加载所有 Locale；路由代码与对应资源可并行预加载，不让组件渲染后逐个发起翻译请求。
- SSR 首屏必须准备好对应资源，并将客户端接管所需的同版本资源随页面传递；不能先显示 key 再补文案。
- 在同一应用或共享包内，按“当前 Locale → 配置中的完整 fallback 列表”查找同一完整 key；不递归展开，不自动追加父语言或默认语言。回退目标必须声明并提供对应内容类型。
- 回退资源独立保存，不把回退文案写回目标语言源文件。记录实际命中的消息语言；ICU 消息按命中语言求值，不能因此改变页面 Locale、用户时区或交易币种。

### 3.3 版本与发布

- 翻译资源与代码同版本发布和回滚，复用构建工具的资源清单、内容哈希和缓存机制，不额外维护独立版本体系。应用使用同次发布的资源，不追随最新翻译。
- 哈希资源使用不可变地址和长期缓存；先上传资源，再切换应用入口。旧发布资源必须覆盖仍受支持的旧页面生命周期，不在新版本上线时立即删除。
- Git 中的资源是发布依据；源文案含义或参数改变时，必须同步复核受影响的译文。TMS 若接入，导入结果也必须通过仓库发布，不直接修改线上资源。
- 翻译上下文与运行时消息分开保存；含糊文案必须注明场景，参数必须注明含义和类型，截图和长度限制按需提供。翻译上下文不进入客户端运行包。
- 品牌名、商品内容等按业务数据处理，不复制成租户文案。当前不提供任意租户覆盖 UI 翻译的能力。

## 4. 消息调用与本地化格式化

**翻译时机**：校验错误、状态选项和异步通知保留 key 与参数，在渲染或通知触发时按当前语言翻译；禁止在模块初始化时固化译文。

- **统一入口**：业务代码通过统一翻译与格式化入口使用当前 Locale，不自行解析语言或创建另一套文案回退规则。key 与参数必须受类型约束；允许有限枚举到 key 的显式映射，禁止任意字符串拼接 key。
- **完整消息**：禁止拼接句子；复数、选择和插值在完整 ICU 消息中表达。翻译只允许受控的富文本标签或组件，不执行任意 HTML，参数不得绕过转义。
- **格式化**：金额保持 `Money { amount, currency }`，展示统一走 `formatMoney` / `Price`，不交给 ICU 直接做货币格式化。数量、百分比、日期等沿用统一格式化策略，同一值不重复格式化；区分纯日期与时间点，纯日期不做时区换算，时间点统一按 `Asia/Shanghai` 展示。SSR 与浏览器使用同一展示时区，不随设备或语言自动变化。
- **业务边界**：切换语言不修改市场、交易币种、时区或计量单位策略。UI API 错误由后端提供 code 与结构化参数，前端生成文案，不直接显示后端原始错误消息。
- **异常**：回退耗尽、参数缺失或消息求值失败时记录消息身份、请求语言、命中语言及资源版本；日志不包含敏感参数。交由组件错误状态或已知可用的通用文案处理，不展示裸 key、原始模板或异常堆栈。
