# 入站校验词表：一条规则一个名字

> 后端细则。速查结论见 `apps/server/AGENTS.md`「硬规则」。前端字段约束的论证见 [field-constraints.md](field-constraints.md)，错误码见 [../error-codes.md](../error-codes.md)，判权码见 [permission-codes.md](permission-codes.md)。细则编号 GEN-52~64。

**同一个形状不许在两个文件里各抄一遍字面量。** 规则定义住在持有该概念的领域类型里，DTO 的 `@Pattern`/`@Size` 只引用常量（`PhoneNumber.*` / `RegionRegistry.CODE_PATTERN` / `cms.dto.LinkTarget.PATTERN` / `UserCouponStatus.PATTERN` / `ProductSort.PATTERN` / `ProductFieldRules.*`）；存在性与语义判定也收在同一类型（`RegionRegistry.requireValidCode`/`requirePrefix` 是 400 话术唯一出口，service 不各写一份 `validateRegion`）。

- **注解元素值必须是编译期常量表达式**（`String.join`、stream 都编不过），所以「常量 == 枚举名/wire 值/区划码」这条编译期查不了，由 `ValidationVocabularyTest`（无库，反射 + 扫 `src/main/java`）在测试期钉，含 switch 分支穷尽性（Java 对 switch 语句不做穷尽检查）和「反证不空转」断言
- **前端字段约束优先引用生成数据**（GEN-58/64）：结构化数字经 OpenAPI → `@hey-api/schemas` → `@shop/api/schemas` 进前端，现有 `common`/app-kit/app 本地出口只做引用。`FieldRuleVocabularyTest` 保留 Java/注解/契约/列宽检查与前端更严格限制、未结构化规则的例外；不再逐项登记生成别名。细则见 `field-constraints.md`
- **改词表 = 改契约**：值会导出进 `openapi/api-docs.json` 与生成的 zod，动一个字符就起后端跑 `pnpm sdk:gen`（`ApiDocsContractTest` 判漂移）。内部收口时替换值必须与被替换字面量**逐字节相同**，含 message 文案
- **形似而概念不同不许合并**：邮编与区划码同为 6 位数字、昵称与收件人同为 30 字，各留一份常量
- **数字规则和形状规则同罪（GEN-56）**：`@Size`/`@Max` 的长度、件数、条数上限只引用常量，owner 是 `common.Quantities`（件数 999 / 车 99 / 行 99 / 券 20）、`common.AddressFieldRules`（收件人 30 / 详址 120 / 智能粘贴整段 500 / 标签 20）、`common.TrackingFieldRules`（code 32 / 名字 50 / 运单号 64 / 轨迹地点 100）、`account.dto.AccountFieldRules`（密码 8 至 72、电话 7 至 20、验证码 6、设备 ID 100、昵称 30、工号 50、图形码 10、refreshToken 200、头像 key 255）、`product.dto.ProductFieldRules`（图 key 255、SKU 名 160、编码 64、维度 10/取值 20、参数 32/64、关键词 128）、`common.NoteFieldRules`（自由文本预算 200，七个入参共用）、`cms.dto.CmsFieldRules`（标题 64 / 副标题 128 / tab 名 32 / key 32 / 子组 30 / 定位值 255 / URL 512——255 与 512 是两个概念）、`coupon.dto.CouponFieldRules`（券名 60 / 发行量 100 万）、`shop.dto.ShopFieldRules`（店名 50 / logo key 255 / 审核备注 255 / 寄件公司名 60 / 邮编 6 位 / 地区规则 50 条 / 不配送地区 100 条）、`product.dto.CategoryFieldRules`（类目名 64 / 类目图标 255 / 属性名 32 / 属性值 64 / 属性值图 512）。分页 `PageParams.SIZE_MAX` 自持（不落在任何列上，是入口防刷闸门）。**一个数字最多同时住五边**（Java 常量 → 编译进注解 → 契约 `openapi/api-docs.json` → 迁移列宽/CHECK → 前端具名常量），由 `FieldRuleVocabularyTest`（无库、反射 record 字段 + 扫迁移和 TS 源）逐条核对。**方向不对称**：入站上限允许比落库更紧（早一步 400 好过脏数据），绝不允许更松（松出去就是 500，引入时抓到的第一个真 bug 是回寄公司门 50 对列宽 32）；DB 是**第二道闸**的那几格（件数走 `CHECK` + `LEAST`）必须与入口**相等**（入口更宽时超出件数被 `LEAST` 静默改小且没人报错）
- **靠结构禁令而非「记得登记」（GEN-61）**：`FieldRuleVocabularyTest` 正则扫 `src/main/java`，`@Size`/`@Min`/`@Max`/`@Pattern`/`@DecimalMin`/`@DecimalMax` 参数里出现数字字面量即红，owner 之外零豁免（清单今天为空，是刻意的）。只 `0` 与 `1` 放行（那是「不为负」与「非空」两句语义）
- **前端具名边界同罪，登记两向核（GEN-64）**：`FieldRuleVocabularyTest` 从六个前端根目录（三端 + 三包 `src`）扫全部 `const X = <整数>`，与三张登记表（契约镜像 / Java 同值 / 策略数字）并集**两向相等**（新增不登记就红，改名/删掉不销登记也红）。裸字面量禁令在结构上看不见**起了名字的抄**（本轮就是这么漏掉购物车 999、商详 99、券发行量 100 万）。登记成「策略数字」的必须填理由，空理由当场红
- **迁移回放跟着搬家改键**：`dbNumbers()` 认识 `ADD COLUMN IF NOT EXISTS x VARCHAR(n)`、`ALTER TABLE x.y SET SCHEMA z`、`ALTER SCHEMA a RENAME TO b`、`RENAME COLUMN`，靠 `rekey` 把已收宽度搬到今天的名字下。否则登记表里那些「落点」停在已不存在的表上、下次真名那格被改窄时方向核对整个失明。注释里 `{@code schema.table.column}` 落点同样跟着改名（迁移脚本里的历史名字不动，那是事实发生过的地方）
- **一个概念不许各说一半**：同一组件上「位数」与「形状」不分居 `@Size(max = 6)` 和 `@Pattern("^\d{6}$")`，形状由位数拼出（`ShopFieldRules.POSTAL_CODE_PATTERN`），由三向核对（注解上限、契约 pattern 原文、从形状反推位数）。取不到位数或那是区间量词就直接抛，不回默认值（回默认值会让门禁在形状变复杂后悄悄失效）
- **注释里的数字等式要有门禁**：「两个数为什么相等」（订单与售后批上限同值、车条目数与下单行数同值）由 `SweepTest`/`FieldRuleVocabularyTest` 从源码各读两数比对，改一处不改另一处会红。注销批上限 20 刻意不等。**文档条数也算等式**：`docs/business-rules/README.md` 索引表「生效/待落地」两列由 `BusinessRulesIndexTest`（无库、纯文本）按顶格 `- **[编号]**` bullet 重数，同时要求索引覆盖规则目录每个 `.md`、无死链、编号全库唯一，并把全仓引用的 `前缀-数字` 比对到真实条目
- **错误码同罪，但码值不进契约（GEN-62）**：`code` 也是裸 `String` 词汇，抛出点只许写 `common.ErrorCodes.X`，字面量只住在 owner 里。与 `@Size` 的关键差别：`code` 的**形状**进了契约（`ApiProblem.code` 是普通 `string`）但**取值**没有，所以加码/改码不需要 `pnpm sdk:gen`（对照：新增扩展键或改某键类型才需要，那是形状变化）。三边（注册表 `contracts/error-codes.mjs` → Java 常量 ⇄ `packages/common/src/contract/error-codes.ts`）、每处状态码、每张卡 `behavior` 分支声明，全由 `ErrorCodeVocabularyTest`（无库）核对：状态码从 `BusinessException` 工厂签名与函数体读出，前端落点从生产源码里真实 `ErrorCodes.X` 引用反查（与 `behavior` 前缀两向相等）。变量码导管只三处（`Validate.isTrue` 形参、两个鉴权过滤器的 `verification.code()`），白名单写成等式，新起第四处就红
- **422 字段级明细带 rule**：`errors[] = {field, message, rule?, min?, max?}`。`rule` 取值只 `common.ValidationRules` 那六个（`REQUIRED`/`MIN_LENGTH`/`MAX_LENGTH`/`PATTERN`/`MIN`/`MAX`），由 `infra.web.FieldValidationErrors` 从 DTO 注解读出（`@Size(max=30)` → `max: 30`；嵌套与数组沿属性路径逐段下钻，**最后一段不去根对象读值**——读了会抛 IAE，异常处理器自己抛就 422 变 500）。`message` 保留（注解上那句中文，进日志、也是前端认不得 rule 时的兜底），别为「参数化」删它。前端词表镜像在 `packages/common/src/contract/validation-rules.ts`，两边相等由 `ValidationRuleVocabularyTest` 核
- **错误体扩展属性只有两格，各带一条通道**：`errors`（字段级 `[{field, message, value?}]`）由 `BusinessException.badRequest(code, detail, errors)` 出，`params`（错误级 `{槽位: 标量}`）由 `badRequestWithParams(code, detail, params)` 出——两条都在 `GlobalExceptionHandler` 挂成 ProblemDetail 扩展属性。**形状已在契约**（`ApiProblem.errors`/`ApiProblem.params`，见 `../error-codes.md` §错误响应契约），词表与取值不在：改槽位名/值不需要 `sdk:gen`，新增扩展键才需要（同时改 `OpenApiConfig` 与这三个键的门禁）。选哪条看**有没有字段可定位**：按表单/DTO 的键标红输入框走 `errors`，没有对应输入框（「最多保存 {limit} 条收货地址」）走 `params`。纪律：`detail` 那句中文仍写完整（日志与中文界面兜底靠它），但句子里的数字/词不由前端解析；`params` 值只收标量，对象与数组一律不放（会顺着上报泄露成第四种形状），用户输入与手机号一类敏感值不进这两格
- **判权码同罪，守卫清单只许一处（GEN-63）**：`@RequirePermission` 码位只写 `common.Permissions.X`，码值字面量只住在 owner 里。代价比错误码贵一档——错误码拼错断一条前端分支，判权码拼错断一次越权且**没有任何测试会红**。词表（有哪些码）不再是手抄：`Permissions.java` 与 `permission-codes.ts` 两份 owner 都由 `pnpm permissions:gen` 从 `contracts/permissions.mjs` 生成，`pnpm permissions:drift` 核回来。`docs/conventions/permission-codes.md` 两张列（`授予`、`消费端点`）不是抄表：前者由 `StaffRole.permissions()` + `SellerGrants.GRANTABLE` 求值生成，后者由注解扫描生成。命名空间守卫同样只一处定义：清单 `RequestPaths.GUARDED_NAMESPACES`、判定 `inNamespace`/`inGuardedNamespace`、自服务豁免 `isAdminSelfService` 由拦截器、两个过滤器、启动自检与本门禁共用。`AdminEndpointGuardTest` 核两条安全等式：命名空间字面量只出现在 owner 与 `@RequestMapping` 路由值；匿名白名单按 `startsWith`、判权按命名空间，两者在真实路由上的分歧（缝里的路由 = 匿名且无判权）必须为零。启动自检另有一道静态版，没有库也仍在跑
- **扫描型门禁共用尺子 `testsupports.SourceScanner`**：走目录、读文件、去注释、指认相对路径此前在八份无库门禁各写一遍（`Files.walk` 四种写法、去注释三种语义），一旦某个门禁因「注释里的字符串被数进去」或「字符串里的 `/*` 吞了下一行」而假绿，没人会去对八份实现。统一实现按路径排序、整段块注释换成一个空格（相邻 token 不粘连）、保留换行（行级锚点照旧对得上）。新增扫描门禁直接用 `javaFiles`/`files`/`read`/`lines`/`withoutComments`/`rel`，别再手写 walk；跳依赖、产物与生成物目录由它负责
- 落点归属跟着「门装在哪一层」走：DTO 上 `@Pattern` 筛选值 → 422（GEN-19 ①），service `Validate.enumFilter` 自判 → 400（GEN-19 ③）。锚点 `ProductControllerTest.非法排序_422带字段名`
