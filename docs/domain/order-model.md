# 订单域模型

> 只写**模型是什么**：实体、字段、状态、金额口径、不变量。
> 不写选型理由（见 [adr/](../adr/)），不写端到端流程（见 [flows/order-lifecycle.md](../flows/order-lifecycle.md)），不写可引用条款（见 [business-rules/order.md](../business-rules/order.md)）。
> 状态：已定案 2026-10-18。字段名与状态取值以本文为准，代码与契约按此对齐。

## 1. 背景

订单域长期有几件事没有定论，每次开发都要临时拍板，且拍完没有裁决依据：

- 是否有主 / 子订单
- 是否支持部分发货
- 是否支持部分退款
- 退款金额按什么算

本文把这几件事一次写死。它们不是四个独立问题，而是同一个根决策——**钱和货的最小独立结算单元是什么**——的四个投影。

## 2. 根决策

> **一次结算 = 一次支付；支付覆盖多个卖家时，按卖家拆成多个子订单。**

| 问题              | 结论                                                                           |
| ----------------- | ------------------------------------------------------------------------------ |
| 是否有主 / 子订单 | 有。主订单 = 一次支付；子订单 = 一个卖家的结算与履约单元                       |
| 拆单依据          | 卖家（交易主体）。结算主体数 > 1 才拆；拆完一律按 1 : N（N ≥ 1）处理，不写分支 |
| 部分发货          | 支持。粒度是「订单行 + 数量」                                                  |
| 部分退款          | 支持。粒度是「订单行 + 数量 + 金额」                                           |
| 退款金额          | 按行商品实付退，不按标价退；运费只随子订单全退退走                             |

拆订单是为了分钱，拆发货单是为了分货，两者独立：同一个卖家从两个仓发货，只拆发货单，不拆订单。

## 3. 实体与关系

| 实体                         | 角色                                                 | 关系                                                                                         |
| ---------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 主订单 Trade                 | 一次支付的载体                                       | 1 : N 子订单                                                                                 |
| 子订单 Order                 | 一个卖家的结算与履约单元，**聚合根**                 | 1 : N 订单行                                                                                 |
| 订单行 OrderItem             | 商品粒度，金额与数量的最小单位                       | 被发货单行、`item` 型退款单行引用                                                            |
| 发货单 Shipment              | 一次实际发出的包裹                                   | 1 : N 发货单行（订单行 + 数量）                                                              |
| 退款单 Refund                | 一次退款                                             | 1 : N 退款单行（挂商品者：订单行 + 数量 + 金额；`shipping` / `compensation` 型不引用订单行） |
| 退款执行记录 RefundExecution | 退款单每一次向支付渠道发起的调用，1 : N 挂在退款单下 | 重试不改退款单，只追加一条执行记录                                                           |

聚合边界：

- **子订单**是聚合根，订单行在聚合内——两者必须同时正确，不允许出现「订单说 2 件、行说 3 件」
- **发货单、退款单**是独立聚合，发货单行与 `item` 型退款单行通过引用订单行 + 事件与子订单协作，不与子订单同事务
- **主订单**只承载支付与金额汇总，不承载履约

订单行是履约与退款的共同载体：发货单行与 `item` 型退款单行都引用它，因此「某件货是否已发、可退多少」由行上的汇总列回答。

## 4. 字段

只列模型必需的列。审计、快照、软删等通用列不在此列。

### 4.1 主订单 Trade

| 字段                                               | 说明                                            |
| -------------------------------------------------- | ----------------------------------------------- |
| `trade_no`                                         | 对外单号                                        |
| `user_id`                                          | 买家                                            |
| `status`                                           | 待支付 / 已支付 / 已关闭                        |
| `closed_reason`                                    | 可空：买家取消 / 超时未付 / 全额退款 / 平台关闭 |
| `item_amount` · `shipping_fee` · `discount_amount` | 金额构成                                        |
| `pay_amount`                                       | 实付 = item + shipping − discount               |
| `paid_amount` · `refunded_amount`                  | 已付 / 已退（含按行退款与运费）                 |
| `compensated_amount`                               | 已付补偿，与 `refunded_amount` 分开计数         |
| `currency`                                         | 一单恒单币种                                    |
| `pay_expire_at` · `paid_at` · `closed_at`          | 时限与时间戳                                    |
| `address_snapshot`                                 | 收货信息快照                                    |
| `checkout_key`                                     | 幂等键                                          |

**不存**「部分退款 / 全额退款」——由 `refunded_amount` 与 `paid_amount` 比较得出。

### 4.2 子订单 Order

| 字段                                                              | 说明                                               |
| ----------------------------------------------------------------- | -------------------------------------------------- |
| `order_no`                                                        | 对外单号                                           |
| `trade_id` · `shop_id`                                            | 所属主订单 / 卖家                                  |
| `status`                                                          | 待发货 / 部分发货 / 已发货 / 已完成 / 已取消       |
| `item_amount` · `shipping_fee` · `discount_amount` · `pay_amount` | 该卖家的应收                                       |
| `paid_at`                                                         | 主订单支付成功的时刻；为空表示未支付，此时禁止发货 |
| `refunded_amount`                                                 | 已退 = 按行退款 + 运费退款，不含补偿               |
| `compensated_amount`                                              | 已付补偿，分开计数                                 |
| `ship_expire_at` · `shipped_at` · `completed_at` · `cancelled_at` | 时限与时间戳                                       |
| `cancel_reason`                                                   | 可空，取值同主订单 `closed_reason`                 |

**不存**「已签收」（物流事实在发货单）、「售后状态」（退款事实在退款单）。

### 4.3 订单行 OrderItem

| 字段                       | 说明                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `order_id`                 | 所属子订单                                                                                       |
| `sku_id` · `product_id`    | 商品标识                                                                                         |
| `name` · `image` · `price` | 下单瞬间快照                                                                                     |
| `quantity`                 | 购买数量                                                                                         |
| `amount`                   | `price × quantity`                                                                               |
| `discount_allocated`       | 分摊到本行的优惠                                                                                 |
| `shipping_allocated`       | 分摊到本行的运费                                                                                 |
| `goods_paid_amount`        | 行商品实付 = `amount − discount_allocated`                                                       |
| `refundable_amount`        | 行实付 = `goods_paid_amount + shipping_allocated`                                                |
| `shipped_quantity`         | **当前有效发货量**，缓存 = 累计发出量 − 退货退款扣回量；仅退款与补偿不动它，因此它不是累计发出量 |
| `refunded_quantity`        | 累计已退数量，缓存                                                                               |
| `settled_quantity`         | **义务结清量** = `shipped_quantity + refunded_quantity`，且 ≤ `quantity`。两个分量互不重叠       |
| `refunded_amount`          | 已退商品款，缓存                                                                                 |

`settled_quantity` 是履约判定的唯一输入：一件货「发了」或「退了」都算结清，两个分量互不重叠，按退款单 `type` 分三种落法：

- **仅退款**（退不会再交付的货）→ 计入 `refunded_quantity`，`shipped_quantity` 不动
- **退货退款**（签收后寄回）→ 退回的量从 `shipped_quantity` **扣回**，同量计入 `refunded_quantity`
- **补偿**（货留买家、只退钱）→ 两个分量都不动，金额单独记 `compensated_amount`

因此买 2 件、发 1 件、把这 1 件退货退款后：`shipped=0`、`refunded=1`、`settled=1`，还剩 1 件未结清——不会误判成全结清。

累计发出量不放在行上，需要时从发货单统计；行上的 `shipped_quantity` 只回答「当前还有多少件货算在卖家发货义务里」。

### 4.4 发货单 Shipment

| 字段                                        | 说明                              |
| ------------------------------------------- | --------------------------------- |
| `order_id`                                  | 所属子订单                        |
| `carrier_code` · `tracking_no`              | 承运商与运单号                    |
| `status`                                    | 待发货 / 已发出 / 已签收 / 已取消 |
| `shipped_at` · `signed_at` · `cancelled_at` | 时间戳，`status` 是它们的镜像     |

发货单行：`order_item_id` + `quantity`。

状态约束：

| 状态   | 可取消         | 可改运单号 | 对行的有效发货量       |
| ------ | -------------- | ---------- | ---------------------- |
| 待发货 | 可             | 可         | 不占                   |
| 已发出 | 可（回退数量） | 不可       | 累加                   |
| 已签收 | 不可           | 不可       | 累加                   |
| 已取消 | —              | —          | 不占，该批行可再建新单 |

**同行多次发货**：一行可出现在多张发货单中，累计有效发货量受发货守卫约束（见 §8）。

### 4.5 退款单 Refund

| 字段                                         | 说明                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `trade_id` · `order_id`                      | 支付归属 / 业务归属（两者都存）                                                                     |
| `refund_no`                                  | 对外单号                                                                                            |
| `type`                                       | 仅退款 / 退货退款 / 补偿（三者按货的去向划分，数量落点见下；`compensation` 型行所在的单取「补偿」） |
| `amount`                                     | 本次退款总额                                                                                        |
| `status`                                     | 待处理 / 已同意 / 待寄回 / 已寄回 / 卖家已收货 / 退款中 / 已退款 / 已拒绝 / 已撤销 / 失败           |
| `reason`                                     | 退款原因                                                                                            |
| `return_carrier_code` · `return_tracking_no` | 退货物流                                                                                            |
| `succeeded_at`                               | 退款成功时刻                                                                                        |

退款单行：`order_item_id` + `quantity` + `amount` + `line_type`。

`line_type` 决定这行钱的落账去向：

| `line_type`    | `order_item_id` | `quantity` | 计入                 | 占可退数量 |
| -------------- | --------------- | ---------- | -------------------- | ---------- |
| `item`         | 必填            | 必填       | `refunded_amount`    | 是         |
| `shipping`     | 空              | 空         | `refunded_amount`    | 否         |
| `compensation` | 空              | 空         | `compensated_amount` | 否         |

- `shipping` 型专用于子订单全退时整笔退 `shipping_fee`（见 6.2）
- `compensation` 型用于不退货、只退钱的情形（买家留货的赔付或纯补偿），不指向具体商品；含它的单 `type` 取「补偿」

三个 `type` 按**货的去向**划分，数量落点跟着走：**仅退款** = 退不会再交付的货（未发件，或拒收 / 拦截后已取消的发货单）；**退货退款** = 退已签收、寄回的货；**补偿** = 货留买家、只退钱。规则见 4.3 与 §8。

**退款执行记录 RefundExecution**：退款单每一次向支付渠道发起的调用落一条记录（请求、响应、渠道流水号、成功与否）。重试不改变退款单 `status`，只追加记录；`status` 只在确认最终结果时推进。

**退款单状态迁移**（唯一真相：`aftersale.model.RefundStatus.TRANSITIONS`）：

| 源态                     | 目标态                  | 触发                                         |
| ------------------------ | ----------------------- | -------------------------------------------- |
| 待处理 `PENDING`         | 已同意 `AGREED`         | 卖家同意                                     |
| 待处理                   | 已拒绝 `REJECTED`       | 卖家拒绝                                     |
| 待处理                   | 已撤销 `CANCELLED`      | 买家撤销                                     |
| 已同意                   | 待寄回 `RETURN_PENDING` | 退货退款：进入回寄等待                       |
| 已同意                   | 退款中 `REFUNDING`      | 仅退款 / 补偿：向渠道发起退款                |
| 待寄回                   | 已寄回 `RETURNED`       | 买家填写回寄物流                             |
| 待寄回                   | 已撤销                  | 买家撤销                                     |
| 已寄回                   | 卖家已收货 `RECEIVED`   | 卖家确认收到退货                             |
| 已寄回                   | 已撤销                  | 卖家确认拦截成功（货已离开买家，买家不能撤） |
| 卖家已收货               | 退款中                  | 卖家确认收货后发起退款                       |
| 退款中                   | 已退款 `REFUNDED`       | 渠道确认成功                                 |
| 退款中                   | 失败 `FAILED`           | 自动重试耗尽，转人工                         |
| 失败                     | 退款中                  | 人工或系统再次发起                           |
| 已退款 / 已拒绝 / 已撤销 | —                       | 终态                                         |

- 仅退款与补偿不经过 `待寄回 / 已寄回 / 卖家已收货` 三态；退货退款必须逐态走过
- 「待处理」只能由卖家同意/拒绝，或买家撤销；「待寄回」只能由买家撤销
- 渠道调用失败只追加 `RefundExecution`，状态停在「退款中」；重试耗尽才转「失败」，再次发起回「退款中」

## 5. 状态

### 5.1 子订单创建时点

**随下单创建，与主订单同事务。** 库存与券按子订单粒度冻结，需要子订单在下单时即存在。

创建时 `status = 待发货`、`paid_at` 为空。发货要求 `paid_at` 非空——未支付的订单不可能发货，因此子订单不需要独立的「待支付」态，未支付这个事实由主订单的支付状态表达。

**跨聚合同事务的唯一破例：** 主订单关单时需在同一事务内取消其下**非终态**子订单（`待发货 / 部分发货 / 已发货`）——聚合生命周期耦合，此时子订单必须与之共同进退。`已完成` 与 `已取消` 是终态，级联不触碰（INV-23）。除此之外一切状态迁移均走事件、不直接写对方字段。

### 5.2 存储的状态字段

| 实体   | 字段     | 取值                                             |
| ------ | -------- | ------------------------------------------------ |
| 主订单 | `status` | 待支付 → 已支付 → 已关闭                         |
| 子订单 | `status` | 待发货 → 部分发货 → 已发货 → 已完成；旁支 已取消 |
| 发货单 | `status` | 待发货 → 已发出 → 已签收；旁支 已取消            |
| 退款单 | `status` | 见 4.5                                           |

原则：**每个实体只管自己那条轴**。跨实体只发事件通知，不直接写对方状态（唯一破例见 5.1）。

例：发货单签收只发事件，子订单收到后判断「我的行都结清了吗、未取消的发货单都签收了吗」，两条都满足才转已完成。履约态允许回退（取消已发出单、退货都会改变结清量），以 §8 的重算为准；上表箭头只表示层级，不表示单向。

### 5.3 展示态投影

买家看到的主进度**不在任何表上**，按以下优先级计算，命中即返回：

| #   | 条件                                                                                      | 展示态   | 决定方 |
| --- | ----------------------------------------------------------------------------------------- | -------- | ------ |
| 0   | 主订单 待支付                                                                             | 待付款   | 主订单 |
| 1   | 主订单 已关闭                                                                             | 已关闭   | 主订单 |
| 2   | 活跃子订单为空（全部已取消）                                                              | 已关闭   | 子订单 |
| 3   | 无任何**活跃**子订单产生过发货，且这些活跃子订单中不存在成功的 `item` / `shipping` 退款行 | 待发货   | 子订单 |
| 4   | 存在活跃子订单未结清                                                                      | 部分发货 | 子订单 |
| 5   | 全部活跃子订单已结清，但未全部完成                                                        | 待收货   | 子订单 |
| 6   | 全部活跃子订单 已完成                                                                     | 已完成   | 子订单 |

- **活跃子订单** = `status != 已取消`。已取消的子订单退出主进度判断，只在售后角标里体现。
- **该子订单产生过发货** = 至少一张 `shipped_at` 非空且未取消的发货单。
- **规则 3 只认商品 / 运费行的成功退款，且只看活跃子订单**：即这些活跃子订单中不存在 `succeeded_at` 非空且含 `item` / `shipping` 行的退款单。已取消子订单自带的成功退款不参与判断（INV-19 / INV-20）。一笔待处理中的请求不会把「待发货」顶成「部分发货」（与第 7 节「只统计已成功退款」同口径）；一笔发货前的成功**补偿**也不会——与第 5.4 节把补偿单单独处理的口径一致。
- 规则 3–6 由「无发货无退款 / 有未结清 / 结清未完成 / 全完成」四个互斥条件穷尽，无死区。
- 规则 4 优先于 5：还有东西没结清时就提示「部分发货」，而不是「待收货」。
- 规则 0 与 1 先判支付生死，再判履约进度；未支付订单不可能有发货单或退款单。
- 全退且从未发货的子订单已在重算时转「已取消」（见 §8），因此不会出现「什么都没发却显示待收货」。

覆盖示例：

| 场景                            | 命中                                           |
| ------------------------------- | ---------------------------------------------- |
| 未支付                          | 0 → 待付款                                     |
| 两个子订单都部分发货            | 4 → 部分发货                                   |
| 一个已完成、一个还没发货        | 4 → 部分发货                                   |
| 买 5 件，已退 2 件、余 3 件未发 | 4 → 部分发货（`settled_quantity` = 2）         |
| 买 5 件，已退 2 件且余 3 件已发 | 5 → 待收货（`settled_quantity` = 5，全部结清） |
| 一个已取消、一个待发货且未发    | 3 → 待发货                                     |
| 一个已取消、一个已完成          | 6 → 已完成                                     |
| 一个已取消、一个已发货未签收    | 5 → 待收货                                     |
| 全部子订单已取消                | 2 → 已关闭                                     |

> 两种「买 5 件、已退 2 件」的区别只在中途还是走完：**退了但剩下没发 = 部分发货；剩下也发了 = 待收货。**

### 5.4 售后角标

退款进度不并入主进度，另算一个角标叠加展示，按优先级取第一个命中的值：

| 角标   | 条件                                                                            |
| ------ | ------------------------------------------------------------------------------- |
| 退款中 | 主订单下存在未完结退款单（含补偿型与重试期内的失败单，见 §8）                   |
| 已退款 | 无未完结退款单，且存在成功的 `item` / `shipping` 行                             |
| 已补偿 | 无未完结退款单、无成功的 `item` / `shipping` 行，但存在成功的 `compensation` 行 |
| —      | 无退款单，或全部为未出钱的终态（已拒绝 / 已撤销 / 失败）                        |

「已退款」优先于「已补偿」是有意的：两者皆有时要让买家先看到钱的去向。

买家最终看到「主进度 · 角标」的组合，如 **部分发货 · 退款中**。两个输出并存，避免用一条线表达两件事。

## 6. 金额

**作用域先定死**，否则实现会分叉：

| 项             | 作用域                     | 说明                                                                                                                                                           |
| -------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定向优惠的定位 | **按各张优惠自身的作用域** | 单品券 → 该订单行；整店券 → 该子订单下所有行；跨店券 → 主订单下所有行                                                                                          |
| 兜底池         | **主订单级**               | `discount_amount` 是主订单总额，池子在全订单层面汇聚，再分摊到**全部子订单的订单行**。每个子订单分到的优惠 = Σ 其行的 `discount_allocated`，INV-3 因此自动成立 |
| 运费分摊       | **子订单级**               | `shipping_fee` 按子订单发生，只在该子订单内的行之间分摊。每个子订单的 `shipping_fee` 各自独立，INV-4 因此自动成立                                              |

### 6.1 分摊口径

按顺序执行，每步写库：

1. **定向优惠逐笔分配**：按上表作用域定位到具体行，可用额度 = 该行 `amount` − 该行已分配优惠
2. **定向超额作废**：额度不足时用尽该行额度，剩余部分**作废、不入订单金额**——一张单品券的余量不能拿去抵无关商品
3. **兜底池逐轮分摊**：兜底池 = `discount_amount − Σ 行已定向分配`。每轮找出第一个「按当前池与占比分配会触顶」的行，让它拿走上限并退出本轮；若无行触顶，则把剩余池按行 `amount` 占比分配给所有未封顶行，分配结束。兜底池仍有剩余但已无未封顶行 ⇒ `discount_amount` 与行金额矛盾，**结算校验失败，拒绝下单**
4. **运费**在子订单内按行 `amount` 占比分摊，同逐轮封顶算法（运费无定向概念）
5. **行顺序** = 创建顺序（行序号自增），余数归行序号最大的行

每轮至少让一行退出，行数有限，故第 3 步必然终止。

例 1 · 定向券被行金额封顶，余量作废：

| 行  | `amount` | 定向分配 | 作废 |
| --- | -------- | -------- | ---- |
| A   | 40       | 40       | 10   |
| B   | 30       | 0        | 0    |

单品券面额 50 定向到 A，A 的额度只有 40 ⇒ 用 40、余 10 作废。`discount_amount = 40`，B 不因 A 的余量受益。

例 2 · 兜底池摊不完，结算拒绝：

| 轮次 | A（上限 40）                      | B（上限 30）                    | 池                    |
| ---- | --------------------------------- | ------------------------------- | --------------------- |
| 0    | 0                                 | 0                               | 80                    |
| 1    | 按占比该得 45.7，触顶拿 40 并退出 | 本轮未参与                      | 40                    |
| 2    | 已退出                            | 按占比该得 40，触顶拿 30 并退出 | 10                    |
| 3    | —                                 | —                               | 10，无未封顶行 ⇒ 拒绝 |

两行额度合计 70 < 池 80 ⇒ 拒绝下单，`discount_amount` 与行金额明细矛盾。

### 6.2 退款口径

行金额拆两部分：`goods_paid_amount`（商品）与 `shipping_allocated`（运费）。

- 退商品金额 = `goods_paid_amount × 退款数量 ÷ 购买数量`，向下取整；该行最后一次退款退剩余额
- **部分退款不退运费**；仅当本次退款后该子订单所有行 `refunded_quantity = quantity`（子订单全退）时，追加一行 `shipping` 型退款行，金额 = 该子订单 `shipping_fee`

口径写死：运费随一次整体履约发生，部分退不减损履约成本，因此不按比例退。运费单独成行，因此不会被行的金额上限拦下，也仍然计入 `refunded_amount`。

### 6.3 补偿口径

- `compensation` 型退款单行的金额计入 `compensated_amount`，**不占可退数量、不计入 `refunded_amount`**
- 补偿因此不会把 `refunded_amount` 推过 `pay_amount`，INV-18 的上限与 INV-22 的等号不会被破坏
- 补偿累计上限由产品另定，模型只保证它与退款两条线互不干扰

### 6.4 常量

金额一律整数分，与 `Money { amount, currency }` 一致；一单恒单币种。

## 7. 不变量

每条都应能写成 DB 约束或测试断言。金额与数量类汇总**只统计 `succeeded_at` 非空的退款单**——待处理、已拒绝、已撤销、失败的请求一律不计入。

| 编号   | 不变量                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------- |
| INV-1  | 主订单 `pay_amount` = Σ 子订单 `pay_amount`                                                       |
| INV-2  | 主订单 `item_amount` = Σ 子订单 `item_amount`                                                     |
| INV-3  | 主订单 `discount_amount` = Σ 子订单 `discount_amount`                                             |
| INV-4  | 主订单 `shipping_fee` = Σ 子订单 `shipping_fee`                                                   |
| INV-5  | 子订单 `pay_amount` = Σ 行 `refundable_amount`                                                    |
| INV-6  | Σ 行 `amount` = 子订单 `item_amount`                                                              |
| INV-7  | Σ 行 `discount_allocated` = 子订单 `discount_amount`                                              |
| INV-8  | Σ 行 `shipping_allocated` = 子订单 `shipping_fee`                                                 |
| INV-9  | 行 `discount_allocated` ≤ `amount`                                                                |
| INV-10 | 0 ≤ 行 `shipped_quantity` ≤ `quantity`                                                            |
| INV-11 | 行 `settled_quantity` = `shipped_quantity + refunded_quantity`，且 ≤ `quantity`。发货守卫读这个值 |
| INV-12 | 行 `refunded_quantity` ≤ `quantity`                                                               |
| INV-13 | 行 `refunded_amount` ≤ `goods_paid_amount`                                                        |
| INV-14 | 行 `refunded_amount` = Σ 该行 `item` 型退款行金额                                                 |
| INV-15 | 行 `refunded_quantity` = Σ 该行 `item` 型退款行数量                                               |
| INV-16 | 子订单 `refunded_amount` = Σ 该子订单 `item` + `shipping` 型退款行金额                            |
| INV-17 | 子订单 `compensated_amount` = Σ 该子订单 `compensation` 型退款行金额                              |
| INV-18 | 子订单 `refunded_amount` ≤ `pay_amount`                                                           |
| INV-19 | 子订单 已取消 ⇒ 已支付时 `refunded_amount` = `pay_amount`，未支付时为 0                           |
| INV-20 | 子订单 全部订单行结清 且 从未产生过发货 ⇒ `status` = 已取消 且 `cancel_reason` = 全额退款         |
| INV-21 | 主订单 `refunded_amount` = Σ 子订单 `refunded_amount`；`compensated_amount` 同理                  |
| INV-22 | 主订单 已关闭 且 `closed_reason` = 全额退款 ⇒ `refunded_amount` = `paid_amount`                   |
| INV-23 | 子订单 已完成 ⇒ 不可转 已取消                                                                     |
| INV-24 | `status` 只能由事实字段驱动，不允许单独写入                                                       |

## 8. 并发与生命周期口径

本节为定案口径，与第 7 节同级约束。

**结清判定**：一行结清 = `settled_quantity = quantity`，即「当前有效发货量 + 累计已退量」达到购买量。两个分量互不重叠（发货后退货会从发货量里扣回），因此不需要封顶去重。

| 项                                              | 口径                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发货量口径                                      | **累计发出量** = Σ（`shipped_at` 非空且 `cancelled_at` 为空的发货单行数量）；行上**有效发货量** `shipped_quantity` = 累计发出量 − 已成功的「退货退款」`item` 行数量。待发货单两者都不算                                                                                                                                                |
| 发货单闸门                                      | 同一订单行最多一张「待发货」状态的发货单，防止同一批行同时存在两张未发出的单                                                                                                                                                                                                                                                           |
| **发货守卫**                                    | 发货前校验 `settled_quantity + 本次发货量 ≤ quantity`。因此「没发就退」过 1 件的行，不会再被发满 `quantity`                                                                                                                                                                                                                            |
| 同行多次发货                                    | 一行可出现在多张发货单，只要满足发货守卫                                                                                                                                                                                                                                                                                               |
| 取消的效果                                      | 取消**待发货**单：释放该行的待发货名额；取消**已发出**单：回退该行有效发货量。两者都使该单不再参与数量统计。取消只可能动未签收件（已签收不可取消），与退货扣回互不相交                                                                                                                                                                 |
| **退款数量处理**（按退款单 `type`，成功时执行） | 「退货退款」退已签收件：`item` 行数量 N ≤ 该行已签收量 − 已退货量（已签收量从发货单统计），N 从 `shipped_quantity` 扣回；「仅退款」退不会再交付的货：N ≤ `quantity − shipped_quantity − refunded_quantity`（未发且未退的额度），超出即拒绝（货留买家的赔付走补偿单）；两者都 `refunded_quantity += N`                                  |
| 拒收 / 拦截 / 丢件                              | 货不会再送到买家：先取消发货单（回退有效发货量，这些货变回未发件），再按「仅退款」退款                                                                                                                                                                                                                                                 |
| 子订单履约态重算                                | 不随历史迁移保留。每次发货 / 取消 / 退款成功后按下述**顺序**处理：**第一步**，`已完成` 与 `已取消` 直接返回，不参与重算；**第二步**，全部订单行结清且该子订单从未产生过发货 ⇒ 转 `已取消`，`cancel_reason` = 全额退款；**第三步**，其余按 `settled_quantity` 映射——全部结清 ⇒ 已发货、有行结清但未全结清 ⇒ 部分发货、全零结清 ⇒ 待发货 |
| 终态护栏                                        | `已完成` 与 `已取消` 不参与重算。已完成后退款（含退货退款）视作售后，不把子订单拉回「已发货」                                                                                                                                                                                                                                          |
| 全退且从未发货                                  | 上表第二步，**优先于第三步的重算映射**。防止买家等一批不存在的货；同时封住「零发货单时完成判定空真」                                                                                                                                                                                                                                   |
| 完成判定                                        | 全部订单行结清**且**全部未取消发货单已签收                                                                                                                                                                                                                                                                                             |
| 未完结退款单                                    | `status ∈ {待处理, 已同意, 待寄回, 已寄回, 卖家已收货, 退款中}`，外加**重试期内**的「失败」单；其余「失败」不在其列                                                                                                                                                                                                                    |
| 退款单闸门                                      | 同一订单行最多一张未完结退款单                                                                                                                                                                                                                                                                                                         |
| 退款重试                                        | 「失败」由**系统**自动重试，每次追加一条 `RefundExecution` 记录，不改退款单 `status`；**重试期内**（自动重试未耗尽且未转人工）按未完结对待，角标显示「退款中」。重试次数与转人工门槛由运维口径另定；耗尽转「失败」，再次发起走「失败 → 退款中」（迁移表见 4.5）                                                                        |
| 撤销触发                                        | 买家仅可在 待处理、待寄回 撤销                                                                                                                                                                                                                                                                                                         |
| 已寄回落拦                                      | 货物已离开买家，不由买家撤销；卖家侧确认拦截成功后，退款单转 `已撤销`                                                                                                                                                                                                                                                                  |
| 退货流向                                        | 已寄回 → 卖家已收货 → 已退款；仅退款路径无中间态                                                                                                                                                                                                                                                                                       |
| 主订单全额退款关单                              | 触发条件：该主订单下全部子订单均处终态（已取消 或 已完成）且 `refunded_amount = paid_amount` ⇒ 主订单转 `已关闭`，`closed_reason` = 全额退款                                                                                                                                                                                           |
| `ship_expire_at` 到期                           | 仅作卖家发货时效的**提醒依据**，不驱动任何自动转移、不关单、不退款；买家的出口是自己取消或申请售后                                                                                                                                                                                                                                     |

## 9. 落地要点

| 需要存在              | 关键约束                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| 主订单表 + 子订单表   | 子订单 `(trade_id, shop_id)` 唯一；主订单 `checkout_key` 幂等                                        |
| 订单行分摊列          | `discount_allocated` · `shipping_allocated` · `goods_paid_amount` 非空                               |
| 订单行数量汇总列      | `shipped_quantity`（有效发货量，退货扣回）· `refunded_quantity` · `settled_quantity`，只累加成功终态 |
| 发货单行表            | `(shipment_id, order_item_id)` 唯一；发货守卫读 `settled_quantity`                                   |
| 退款单表 + 退款单行表 | 退款单行 `line_type` 三值；未完结闸门按订单行唯一；退款数量按 `type` 校验（见 §8）                   |
| 退款执行记录表        | 挂退款单，每次渠道调用一条；重试只追加记录                                                           |
| 状态迁移表            | 每个实体的合法迁移集中定义，条件更新 + 影响行数做并发闸门                                            |
| 退货物流字段          | 退货退款类型必填，仅退款为空                                                                         |
