# 三端发布前冒烟矩阵

每次发布共享 UI、SDK 契约或权限改动后执行。失败只记录结果，不在发布过程中直接改代码。

| 端     | 登录                     | 列表                     | 详情                                                      | 表单                     | 权限                       | 错误态                           |
| ------ | ------------------------ | ------------------------ | --------------------------------------------------------- | ------------------------ | -------------------------- | -------------------------------- |
| web    | 密码登录、刷新、退出     | 首页 feed、商品列表      | 商品详情、订单详情                                        | 地址、结算、售后         | 未登录受保护页、过期 token | 空态、接口失败、重复提交         |
| seller | 手机号密码登录、店铺切换 | 商品、订单、售后列表     | 商品编辑（订单侧只有发货/售后决策浮层，无独立订单详情页） | 发布商品、发货、售后决策 | X-Shop-Id、无权限子账号    | 校验失败、状态冲突、上传失败     |
| admin  | 工号登录、刷新、退出     | 用户、员工、店铺、优惠券 | 物流轨迹与异常单（管理端没有订单页）                      | 审核、封禁、券作废       | STAFF_MANAGE、COUPON_OPS   | 409 状态冲突、404 边界、查询失败 |

矩阵里的「详情」列按各端**真实存在的落点**写：卖家与平台的订单都是列表内就地处置（发货、异常单结单），
没有 `/orders/$id` 那样的详情页——只有买家端有。写一个不存在的页面不是加覆盖面，是让冒烟的人白找一圈后跳过这一格。

最小执行顺序：登录 → 打开列表 → 打开一条详情 → 提交一个可撤销表单 → 触发一次权限拒绝 → 断开后端验证错误态。
